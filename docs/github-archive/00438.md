Only the assistant had a per-address limit, so refresh spam or a script could call the rest of `/api/*` as fast as it liked. That is open-source hosting with no budget for runaway load.

**What changes**
- New middleware `server/lib/apiRateLimit.ts` runs before every `/api/*` handler. Past 1,200 requests in a minute from one address, it answers 429 with `retry-after`.
- The limit is set by `API_RATE_PER_MINUTE`; 0 turns it off.
- Map tiles and vehicle models are not counted, because one view fetches many byte ranges. Requests with no client address (local dev, tests) are not limited either.
- It reuses the assistant's rolling-window limiter, so the memory bound and the oldest-first eviction are the same.

**How to verify:** `npx vitest run server/lib/apiRateLimit.test.ts` covers the limit, the reset after a minute, the tile skip and the off switch.

**What stays the same:** the assistant's own fair-use limits and daily budget. The Cloudflare edge rule is still for the owner to set in the dashboard.
