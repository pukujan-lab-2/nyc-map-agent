**Problem.** The trip planner container (`nyc-map-otp`) loads the whole app env file, so anyone who can run `docker inspect nyc-map-otp` on the host sees the Octo, InferHub, MTA, Socrata, Mapillary and CD secrets. OpenTripPlanner reads none of them.

**What changes.** The `otp` service in `deploy/docker-compose.yml` no longer has an `env_file`. It keeps `JAVA_TOOL_OPTIONS` and its graph volume. `checkpoints/CURRENT.md` records the change.

**How to verify.** After merge, on the host: `docker compose up -d otp` in `deploy/`, wait for the graph to load, then check that `docker inspect nyc-map-otp --format '{{range .Config.Env}}{{println .}}{{end}}'` lists only Java and OTP variables, and that a trip question in Ask still returns a route.

**What stays unchanged.** `web` and `cd` keep the env file. CD never recreates OTP, so nothing changes on the live host until OTP is recreated by hand; trip search pauses for the minute or two the graph takes to load.
