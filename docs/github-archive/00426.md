On the live site I asked "Which way out for the Empire State Building? I'm at 34 St-Herald Sq station." The agent said to walk "up Broadway about three blocks to West 34th Street & Fifth Avenue". That's wrong: it's one block east along 34th Street. The agent had no tool for station exits, so it made up the walk. This is scene 2 of the demo video (#418).

What changes:
- **A new `station_exit` tool.** It takes the station as the rider names it ("Herald Sq") or "here", plus the place they're going. It finds the station; when several share a name, it uses the one nearest the destination. It picks the exit nearest the place from the station's entrance list, using the same `portalFor` code that trips already use. It returns the exit by direction and street, the escalator and elevator outages, and the walk from the exit with its turns and a trip id. The answer gets a "Show the exit" pin and a "Show the walk" button.
- **A new prompt rule.** It sends "which way out" questions to that tool, asks for the exit, then the walk in order, then "Want to start?", and forbids describing a walk from a station without a routing tool.
- **Walk turns onto unnamed paths are dropped.** "Turn right onto the path" was reaching the model and telling the rider nothing.
- **Pin labels drop the address.** "Show Bryant Park" now, instead of "Show Bryant Park, Manhattan Community Board…".

How to check: the new unit tests cover finding a station by its short name, choosing between same-named stations, and pin names. I also ran the tool once against live data for Herald Square to the Empire State Building. It returned the south exit on Broadway, a 4-minute (285 m) walk, both escalator outages, and the two buttons. After deploy, ask the live agent the same question.

What stays the same: trip answers keep using `transit_plan`'s recommended exit. Elevator-only questions still go to `elevator_status`.
