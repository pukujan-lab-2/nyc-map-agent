Asking "How do I get to Aldi at Rego Park?" took 27 seconds and showed the wrong place, and for the last 9 seconds the screen looked frozen. We also had no record of how long requests take, so slow or stuck answers couldn't be found.

## What changes

1. **Faster first answer** (`model-fallback.ts`):
   - **Thinking off.** The model's hidden "thinking" is now off for DeepSeek and Qwen. With the real prompt and tools, the first step came in 1.2 s instead of 2–2.5 s.
   - **Slow-start switch.** A model that hasn't started within 6 seconds is dropped for the next backup model. The last model in the list is always waited for.
   - **Backups.** The server's backup list is now `ali/qwen3.8-flash` (1.0 s to first step), then `cbcn/deepseek-v4-flash`.
2. **Timing for every request** (`runLog.ts`, migration `20261024010000_agent_runs.sql`):
   - **What's recorded.** One `[agent-run]` log line and one `core.agent_runs` row, with: time to first step, time to first words, each tool's time, the model that answered, tokens, and the outcome (done, error, aborted or stuck).
   - **Stuck requests.** A request still running after 45 seconds is written as `stuck` straight away.
   - **Privacy.** No question, answer or location is stored. Rows older than 30 days are dropped.
3. **Never looks frozen** (`AgentHome.tsx`): once every step is done, a spinning "Writing the answer" row appears. After 8 seconds a "Still working" note shows.
4. **Stores by name** (`services.ts`): "Aldi at Rego Park" now resolves to *Aldi, 61-11 Junction Boulevard, Rego Park* through OpenStreetMap's Nominatim. The search covers the five boroughs, takes only business results, caches each search for a day, and falls back to GeoSearch for addresses and on failure.
5. **Flaky test fixed:** `audit.test.ts` now uses a fixed clock. On main it failed at 6:50 PM because the time "50" counted as a number the reply was allowed to repeat. This is why #405 didn't deploy.
