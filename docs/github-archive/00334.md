# Issue #334: Filters that are on do not show on the street-view mini map

- State: closed (2026-10-25)
- Opened by Pukujan on 2026-10-23
- Original: https://github.com/Pukujan-lab/nyc-map-agent/issues/334

## Summary

The street-view corner map does not show the things the person turned on in Layers. A filter that is on should draw those places inside the mini map that is already open.

## Symptoms

1. **Filters stay on the main map**: Restrooms and the other Layers switches draw on the big map. The corner map in street view does not draw them.
2. **The inset is a fixed slice**: It keeps land, water, parks, streets, subway lines, stations, and live vehicle dots. It does not take the filter layers.

## Evidence

The person's words: "filters should show things in current mini map?"

On `main`, `keepInMini` in `src/lib/map/miniStyle.ts` keeps the background, water and park fills, street lines, and the transit line, underground line, station, and bullet layers. `StreetMiniMap` then adds live vehicle dots within about 900 m. The style is copied when the inset is created. Turning a filter on afterwards does not add that filter's layer to the inset.

Pull request #324, still open, adds flat building footprints, a You dot, a facing label, and restroom dots that can be tapped. It does not copy the other Layers filters into the inset. It is not merged.

## Hypotheses

**The inset never receives filter layers.** Status: supported by `keepInMini` on `main`. Would confirm: with Restrooms on, the main map shows restroom icons and the street-view inset shows none. Would refute: the inset shows the same restroom icons as the main map while that filter is on. Experiment: turn one filter on, enter street view, and compare the two maps. This filing did not run that check on the live site.

## Counter-signal

The inset does show subway lines, stations, and nearby live vehicles, plus park and water fills from the base map. Those are always part of the inset. The missing pieces are the switches the person turns on and off.

## Honest caveat

The sentence is a question. This log reads it as: places for every filter that is currently on should appear in the street-view mini map. The full list of filters, and whether a tap on each kind opens its sheet, was not spelled out. The live site was not opened for this filing.

## Problems vs gaps

Problem: an on filter's places are missing from the corner map.

Gap: the inset has no path that follows those switches. *(proposal)* Showing every on filter inside the current mini map does not exist. Pull request #324 draws restrooms only, and only on that branch.
