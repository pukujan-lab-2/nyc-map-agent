Closes #237. Follow-up to #235.

**Ask in street view.** There is now a labelled **Ask** button in the street-level strip (WalkControls) and in the Mapillary street-view header. It opens the same assistant as a compact sheet that doesn't block the view. Inside the Mapillary dialog the sheet portals into the photo area so it stays clickable. The request carries an optional `context` (zod in schema.ts, mirrored in openapi.ts) with lon/lat, heading, nearest station and nearest entrance (from the loaded subway static data), and the followed train. The server adds it to the system prompt for that request only and uses it as "here" when no location was shared. Nothing is stored.

**Hands-free.** There is a labelled **Hands-free** toggle in the assistant header. It runs listen → send → speak → listen until tapped off, using the existing `useSpeech` (Web Speech API). Where speech recognition isn't available the toggle is disabled with a tooltip. If the mic is blocked or missing it turns itself off rather than retrying.
- The mic starts only after a tap on the toggle.
- A visible status row shows Listening / Speaking (mic off) / Thinking, with the line "Nothing is recorded or saved."
- The mic stays off while the app is speaking, and there's a 350 ms gap before it listens again.
- Transcripts go only to the request. Nothing is stored or logged, there are no popups, and no new dependencies.

**Tests**
- `src/features/agent/askStreet.test.ts`: nearest station and entrance, the context passing the schema, and the hands-free listen and stop rules.
- `contract.test.ts`: the mounted route accepts the context and the prompt names it.
- `e2e/ask-street.spec.ts`: a fake Web Speech run through street level → Ask → answer → Hands-free loop.
