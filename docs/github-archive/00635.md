The speech-to-text endpoint sent voice recordings to Groq's hosted Whisper by default, which the owner did not choose, and voice was off on the live site.

## Human outcome

Voice in Brave, Firefox and on phones works in many languages, and the recording never leaves the owner's own machines: it goes to the Whisper server already running on the MacBook Pro.

## Before and after

**Before:** with `GROQ_API_KEY` set, `/api/stt` posted every recording to `api.groq.com` (added in #401). On the VPS no key was set, so the mic said "Voice isn't set up on this server yet". `docs/PRIVACY.md` does not say audio leaves the server.

**After:** no Groq name, URL or key remains in code, tests, env templates or docs. `/api/stt` answers 503 unless `STT_BASE_URL` is set. With `STT_PROTOCOL=speech` it calls the copilot speech server on the Pro (`POST /stt?stack=multilingual&lang=`), which runs Whisper large-v3-turbo on the Apple GPU. The browser now converts its recording to a 16 kHz WAV first, because that server reads WAV and not the webm or mp4 a browser records. Any OpenAI-compatible Whisper server still works with `STT_PROTOCOL=openai` (the default).

## Change and scope

- `server/features/agent/stt.ts` and `stt.test.ts`: no default host, optional key, the `speech` protocol, a 60-second timeout for it (a stack swap takes about 30 seconds).
- `src/lib/voice/serverStt.ts` and its test: `toWav16k` and `encodeWav`; falls back to the original clip if the browser cannot decode it.
- `.env.example`, `deploy/.env.example`, `deploy/README.md`, `docs/PLAN-copilot-port.md`: wording and a Voice section.
- `tasks/TASK-NMA-0006-remove-groq.md` and the checkpoints.

## What stays unchanged

The rate limits and the chat. The VPS env file (outside git) is set after this deploys: `STT_BASE_URL=http://host.docker.internal:18799`, `STT_PROTOCOL=speech`, `STT_STACK=multilingual`.
