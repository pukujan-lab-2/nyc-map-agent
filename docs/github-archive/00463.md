The post-deploy contract test on main is failing: asking for a store logo by an id Wikidata does not know returns a 502 error page instead of "no logo".

## What changes

- **Unknown ids answer 404 `no_logo`.** `/api/v1/storefronts/logo?qid=Q50` checks the brand's logo on Wikidata, the open database of brands and places. Q50 no longer exists there, so Wikidata answered 404. The route treated that as an upstream failure and returned 502, and Cloudflare replaced it with its own error page.
- **Nothing is stored for an unknown id.** Before, any made-up id would have added a row to `core.brand_logos`, the table of brand logos already looked up.
- **A real Wikidata outage still answers 502**, so it stays visible.

## How to verify

- `pnpm exec vitest run server/features/storefronts` passes, including two new route tests: the unknown id answers 404 and stores nothing; an outage still answers 502.
- After the deploy, this should answer 404 instead of 502:

```bash
curl -s -o /dev/null -w '%{http_code}\n' 'https://nyc.design-bakery.com/api/v1/storefronts/logo?qid=Q50'
```

## What stays the same

Known brands resolve and serve their logo exactly as before.
