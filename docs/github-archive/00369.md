# Issue #369: Protect the API and model budget: idle tabs, rate limits and fair use

- State: closed (2026-10-25)
- Opened by Pukujan on 2026-10-24
- Original: https://github.com/Pukujan-lab/nyc-map-agent/issues/369

The project is open source with no budget for runaway costs. Tabs left open, page-refresh spam, and heavy use of the chat agent could all raise costs without limits in place.

## Evidence
- Hidden tabs already stop polling (TanStack Query's default); visible idle tabs keep polling.
- No rate limiting was found on `main` for `/api/agent` (searched `server/`); the earlier PR #200 had caps and a rate limit but is unmerged and mostly superseded.
- A model fallback chain and busy-retry exist (`server/features/agent/model-fallback.ts`, #343).

## What is needed
- After about 10 minutes without interaction in a visible tab, pause live updates and show "Paused — tap to resume".
- Rate limits in two layers: a Cloudflare per-IP rule on `/api/*`, and Caddy at the origin.
- Agent fair use, with no credits and no "upgrade" wording: a rolling window per device and IP plus a short burst limit. Proposed numbers (not yet confirmed by the owner): 20 questions per 3 hours, about 5 a minute. The message says when the next question frees up; the map, restrooms and no-model answers keep working.
- A global daily spending cap that switches to the cheapest model or no-model answers.
- Check that the origin has no public ports beyond the Cloudflare tunnel.

## Acceptance criteria
- [ ] An idle tab stops polling and resumes on tap.
- [ ] Rapid repeated requests from one IP are limited at the edge and at the origin.
- [ ] The agent's limit message names the wait time and never mentions payment.
- [ ] Reaching the daily cap degrades the agent without breaking the map.

**Pukujan commented, 2026-10-25**

#438 adds the origin-side limit: one address gets a 429 with a wait time after 1,200 API requests in a minute (`API_RATE_PER_MINUTE`, 0 turns it off). Map tiles and vehicle models are not counted. With the agent's own limits, the daily budget and the idle pause already on main, the app side is complete. What remains is the Cloudflare rate-limit rule on `/api/*`, which is set in the Cloudflare dashboard.

---

**Pukujan commented, 2026-10-25**

The Cloudflare rate-limit rule is now live on design-bakery.com. Requests to `nyc.design-bakery.com/api/` are blocked for 10 seconds once one IP (per Cloudflare data center) sends more than 200 in 10 seconds. That matches the origin's own 1,200 a minute (#438), so normal use never reaches it. The edge now turns away floods before they reach the server. The app-side pieces (idle-tab pause and the agent fair-use budget) were already on main, so this closes the issue.
