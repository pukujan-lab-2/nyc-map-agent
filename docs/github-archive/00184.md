# Issue #184: Every 3D subway train shows 'A' on its front and rear signs

- State: closed (2026-10-25)
- Opened by Pukujan on 2026-10-21
- Original: https://github.com/Pukujan-lab/nyc-map-agent/issues/184

## Problem
Every 3D subway train model (added in #165) shows an **A** on its front and rear route signs, whatever line it actually runs. A Q train in Midtown reads as an A train, so the 3D view tells you the wrong line.

## Symptoms
1. **Same letter everywhere**: every subway model shows A on both end signs.
2. **Colour ignored**: the sign never takes the line colour (N/Q/R/W yellow, 4/5/6 green, and so on).

## Hypotheses
- **H1, the sign is part of the shared model texture** — *Status: confirmed.* The R142 glTF (graphics model file) is drawn as one instanced mesh per part with the model's own material, so its baked sign texture is shared by every train, and the vehicle layer is never told the route (`VehicleInstance` has no route field). *Would refute:* any per-instance texture or route input in `createVehicleLayer`; there is none.
- **H2, a texture cache keyed without the route** — *Status: refuted.* No sign texture is generated for vehicles at all.

## Proposal *(proposal)*
Pass the route into the vehicle layer and draw each train's own route bullet on the front and rear signs, cached as one texture per route and disposed when no train on that route is in view.

**Pukujan commented, 2026-10-25**

The cause is gone. Since #366, 3D trains are boxes in the route colour with the route bullet above them; the R142 model with the fixed 'A' sign was removed (`src/lib/map/threeLayer.ts`, `docs/DESIGN_RULES.md`).
