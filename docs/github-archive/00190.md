# Issue #190: Asset publish never deletes old Octo file versions

- State: closed (2026-10-23)
- Opened by Pukujan on 2026-10-21
- Original: https://github.com/Pukujan-lab/nyc-map-agent/issues/190

## Problem
Every rebuild of a large static asset (PMTiles, geojson, glb) uploads a fresh multi-part copy to Octo files (stored in R2) and repoints `core.published_assets` at it, but the old copy is never deleted. Today that left about 680 MB of orphaned old versions (being cleaned up separately).

## Symptoms
1. **Storage grows per rebuild**: each publish adds one full copy of the asset; nothing removes earlier copies.
2. **No rollback record**: once the row is overwritten, the previous version's file ids are lost, so they can be neither restored nor safely deleted.

## Proposal *(proposal)*
- New migration: `previous_parts jsonb` (plus `previous_etag`, `previous_total_bytes`) on `core.published_assets`.
- Publish flow: upload, verify (every part fetchable, total bytes and sha256 etag match), swap (current moves to previous), then delete Octo files of the version that was previous before the swap. Never delete current or previous file ids; on failed verification delete nothing and keep the old pointer.
- `--dry-run` flag; unit tests for the prune selection.
- A 403 on delete (key lacks the `delete` scope, or role is not owner/admin) logs `prune skipped: key lacks delete scope` and does not fail the publish.
