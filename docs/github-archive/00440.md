When the daily budget ran out or the model failed, every question got the same "resting" or "failed" message. That included the two questions people ask most in a hurry: where the nearest restroom is, and whether their train is running.

**What changes**
- `server/features/agent/noModel.ts` recognises those two questions. It recognises restroom words in English and Spanish, and a subway line given by its capital letter or number, so "take a train" is not read as the A.
- It then runs the same tool the model would use (`nearest_restroom` or `line_status`) and writes a short answer from the result. The buttons under the answer are the same as a model answer's.
- `routes.ts` uses it in three cases: the daily budget is spent, the model stream errors before any text, or the call throws. Any other question keeps the usual message.

**How to verify:** `npx vitest run server/features/agent/noModel.test.ts server/features/agent/routes.test.ts`. These cover the question matching, a restroom answer with its walk, the no-location prompt, a quiet line, and the route answering a line question with no model call once the budget is spent.

**What stays the same:** with a working model, nothing changes. The model still gets every question first.
