The API had no version in its paths and `openapi.json` said `version: "1"` regardless of the release, so there was no way to signal or gate a breaking change.

**What changes**
- Every route is served at `/api/v1/*` (canonical) and at `/api/*` (alias, same handler, marked `deprecated: true` in the spec). `POST /api/v1/agent` and `/api/v1/openapi.json` included. The gzip skip-list understands both prefixes.
- `info.version` comes from `package.json` (`0.1.0` today; release-please bumps it), via `API_INFO` in `server/openapi.ts`, used by both the served doc and `pnpm openapi`.
- CI `api` job: `scripts/ci/api-breaking.sh` runs oasdiff 1.34.0 against the base branch; a breaking change now passes only if `info.version`'s major is higher than the base's.
- `server/app.test.ts`: both prefixes return the same spec and the same 400 body; every alias has a `/api/v1` twin and is deprecated; unknown `/api/v1/*` is the JSON 404.

**Verify:** `oasdiff` against `main`: 0 breaking, 40 info (`endpoint-deprecated`). Gate script: removing a path fails at major 0, passes with `1.0.0`. `pnpm test` 167 pass.

**Unchanged:** handlers, query validation, response shapes; the app still calls `/api/*` (moving the client to `/api/v1` is in #205).

Closes #204
