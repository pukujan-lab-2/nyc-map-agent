The app called its own API through hand-typed `fetch` strings, and nothing checked the running server against `openapi.json`. A renamed query parameter or a changed response would only show up as a broken panel on someone's phone. Now the calls are typed from the spec, and CI checks the live server against the spec after every deploy.

**What changes**
- **Generated types:** `pnpm openapi` now also writes `src/lib/api/schema.d.ts` with openapi-typescript. `pnpm openapi:check`, which already runs in the `api` CI job, fails when either file is stale.
- **Typed client:** `src/lib/api/client.ts` exports `api`, an openapi-fetch client of about 2 kB. Events, place toilets, parking rules, street levels, the hourly and live weather, ferries and traffic now call through it. The UI components are unchanged.
- **Contract job:** after `deploy` on main, a new `contract` job runs Schemathesis against nyc.design-bakery.com. It sends two generated requests to every read-only `/api/v1` route and checks for server errors, response shape and content type. The agent and speech-to-text routes are POST and are skipped, because each call costs money. The vehicle-model route is skipped too (see below).
- **Spec fixes the contract test found:** the block and city tile routes send `application/vnd.pmtiles`, and the vehicle-model route sends `model/gltf-binary`. The spec didn't list either type; now it does. `application/octet-stream` stays listed beside them, so the change doesn't break existing clients.
- **One mismatch left as it is:** `/api/vehicle-models/{mode}` doesn't declare its `mode` parameter. The oasdiff gate counts adding that declaration as a breaking change, and it would need a major version bump. So the contract job skips this one route for now.

**Evidence**
- The types caught a real mismatch on the first typecheck: the spec says `lat` and `lon` are numbers, and three callers were passing strings. They now pass rounded numbers. The URL text is the same, which the new test checks.
- Schemathesis 4.0.0 against the live site, run with the corrected spec and the exact flags in the CI job: all 29 read-only `/api/v1` routes passed (53 generated requests, no failures). Before the fix, it reported the two tile content-type mismatches and the undeclared parameter.
- Nothing this change could break failed: 1237 unit tests pass, including the 2 new client tests (one checks query parameters, the other a path parameter). Typecheck, lint, module boundaries, knip and the size limits are clean (main bundle 510 kB of 535 kB).

**What stays the same:** every route's behaviour, the URLs the app requests, and the oasdiff breaking-change gate.

**Caveat:** the contract job runs only after a deploy to main, not on pull requests. A pull request's spec can describe routes the live server doesn't have yet.
