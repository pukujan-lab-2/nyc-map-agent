# Issue #164: Tapping a building at street level opens no details panel

- State: closed (2026-10-21)
- Opened by Pukujan on 2026-10-21
- Original: https://github.com/Pukujan-lab/nyc-map-agent/issues/164

Tapping a building at street level opens nothing. In the first test of the eye-level picking work (an uncommitted `eyePick.ts` that casts the camera ray through the tap), the ray found the building but the details panel never appeared.

## Symptoms

1. **No panel on a facade tap.** At Park Av S and E 21 St, bearing 300, a tap on the storefront facade at screen centre leaves the map unchanged.
2. **The ray is right.** The ray hit reports a building (`store: 1`, 53 m tall) about 45 m ahead, so the miss happens after picking.

## Hypotheses

- **Block lookup by grid key** (confirmed). The tap looks its block up with `blockKey()`, the 0.003° grid key, but real blocks are tax blocks keyed by their own ids such as `100850`. The lookup returned nothing for every tap, and the code then returned early. Would confirm: the lookup is empty while 20,276 blocks are loaded. Experiment: log both keys in the dev build. Result: grid key `13579:-24663`, block keys look like `202835`.
- **Panel hidden at street level** (confirmed). `MapPanel` returns `null` whenever `walking` is true, so even a correct selection, a landmark or a storefront pushed with `showPanel` cannot show. Would refute: the panel appears once the block is found. It did not appear until this guard changed.

## Proposal

Find the block by testing which block polygon holds the ray's hit point. Let the panel open at street level only when a tap there opened something, so a selection carried in from overhead does not cover the street on entry.
