**Problem.** On a weekday there was no way to see weekend work on the map. The line panel and the map's alerts only showed alerts running right now. So the 7's weekend work at Flushing was invisible until it started, and a rider planning Saturday had nothing to look at.

**What changes**
- **Line panel.** It gets **Now / This weekend** chips. "This weekend" means Friday 9 pm to Monday 5 am, New York time. It lists the work booked in that window, says when nothing is planned, and leaves out the live held-train notices, which only apply right now.
- **Alerts API.** `/api/transit/alerts?from=&to=` returns alerts in effect at any time in the window: whole hours, at most 4 days, cached for 5 minutes. A call without a window is unchanged.
- **Line answers.** A line answer about "this weekend" checks across the whole weekend, not one instant, so Sunday-only or overnight work counts too. Its button, "Show the 7 work this weekend", opens the panel on that weekend; on desktop it opens on its own. Asking about one day, such as "Saturday 2pm", opens that day.

**How to verify.** Open any line, tap "This weekend", and the weekend's planned work should be listed. Ask "Any problem with the 7 this weekend?" and the 7 should open on its weekend view.

**Unchanged.** The default view is still Now. Live delays, outages and the map's station markers still show what is running now.

Builds on #554. New tests: the weekend window (including the clock change), a Sunday-only alert in `line_status`, alert windows, and a layout e2e for the chips on a phone and desktop.
