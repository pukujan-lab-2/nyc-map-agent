# PR #210: fix(trains): keep live trains from moving backward

Closes https://github.com/Pukujan/nyc-map-agent/issues/208

Stacked on #195 (same dwell/motion code).

**Root cause:** `estimateTrain` is stateless. Every tick it recomputes the position from the latest ETAs. When an update delays the next arrival, or drops the stop just passed (so we extrapolate back from the next one), the new estimate is behind the drawn train and it jumps back. It could also run past a stop the feed hadn't released yet.

**Fix:** `monotonic.ts` adds a small per-trip `ProgressTracker` used by the map layer and the train card:
- progress along the route never decreases for the same trip; a new trip, route change or a >2 km backward jump (reroute) resets it
- the train can't pass the first stop the feed still lists until the feed drops it
- when the estimate falls behind, the train keeps creeping toward the next stop so it arrives on the new ETA

**Tests:** `monotonic.test.ts` reproduces the backward jump without the tracker, then checks monotonic motion, the hold at an unreleased stop, reroute reset and reverse-direction trips. Dwell tests from #195 still pass. Gates script passes.
