**Problem.** Asking a question within 5 seconds of the last one (for example, right after tapping **Use my location**) got a refusal as the answer: "One moment between questions, please. Your next question frees up in about 1 seconds…". The person had to ask again. While an answer was still coming, the send button was also disabled, so a corrected question couldn't be sent.

**What changes**
- The client waits out the server's gap between questions (5 seconds, the server default) before sending. During the wait the answer card shows **"Sending in a moment…"** (in all 8 app languages) and no refusal text. New file: `src/features/agent/askSpacing.ts`; `askAgent` in `src/features/agent/stream.ts` uses it.
- If the server still refuses with a short wait (15 seconds or less, for example another tab on the same address), the client waits the server's `Retry-After` time and retries, up to twice. A long fair-use refusal is still shown as before.
- A newer question replaces an older one immediately. The held question is dropped (its bubble too), and an in-flight answer is aborted. The server already records an aborted run as `aborted`. Send stays enabled while an answer is coming.
- Server wording: "in about 1 second", not "1 seconds".

**What stays the same.** The server's per-address spacing and the rolling question window in `server/features/agent/fair-use.ts` are unchanged. They remain the safety net for later spending caps.

**How to verify**
- New tests in `src/features/agent/askSpacing.test.ts` cover these cases: a second question is held, then sent with no refusal; a short 429 is waited out and retried; a long 429 is still shown; and a held question that gets replaced never goes out. The fair-use tests now include the "1 second" wording.
- On https://nyc.design-bakery.com, ask two questions within a few seconds. Both get answers, and neither shows a refusal. If the second one is sent while the first is still waiting, it replaces the first.
