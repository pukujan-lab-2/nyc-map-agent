**Problem.** The event search's Tavily-to-TinyFish fallback had only two tests: one for when Tavily has results and one for when it returns a server error. Timeouts, network failures, how the key is sent, and the TinyFish-only setup were untested.

**What changes.** Tests only. This branch began as its own Tavily-first search. Main shipped the same behaviour in #422, which also uses Tavily to read pages, so the branch was rebuilt on main. It now keeps only the tests main was missing:
- falls back to TinyFish when Tavily times out, returns nothing, or the network fails
- sends the Tavily key as a bearer header, never in the URL
- goes straight to TinyFish when only its key is set
- returns an empty list, not an error, when both providers answer with nothing

**How to verify.** `pnpm -s exec vitest run server/features/agent/webLookup.test.ts` passes all 12 tests.

**Unchanged.** No app code, keys or environment files.

**Gap noticed (not fixed here).** When only the Tavily key is set and Tavily fails, `webSearch` returns `{ results: [] }`. The agent then reads that as "no event found" instead of "the lookup failed", because `tavilySearch` returns `null` for both a failure and an empty answer. A small follow-up could tell the two apart.
