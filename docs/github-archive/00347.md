Tapping a bus stop icon on the map did nothing, so a person could not see which routes serve a stop or when the next bus comes.

## What changes
- Tapping a bus stop (with the bus stops layer on) opens a sheet with the routes that serve it and the next buses with arrival times.
- New server endpoint `bus-arrivals?stop=MTA_…` reads the MTA's live stop feed and returns arrivals soonest first. It is added to the OpenAPI file.
- `MapView.tsx` gets the tap handler; the sheet, two data hooks and the nearest-stop and arrival-text helpers are new.

## How to verify
- Automated: `busStop.test.ts` and the new `bus-arrivals` server tests pass; 165 tests in the transit, server and map folders pass; typecheck and lint ran clean on the touched files.
- By hand, once deployed with the bus key: turn on bus stops, zoom in, tap a stop icon.

## What stays unchanged
The follow card, QuickLayers and ViewSwitcher. `MapView.tsx` gets one small change, and the draft top-bar PR (#341) also edits that file, so expect a small textual conflict.

## Not checked
It was never tried in a running app, and the real MTA response shape and the 16px tap tolerance are untested; the parser follows the existing `bus-trip` code. Two unrelated test files timed out importing maplibre-gl on a heavily loaded machine; this was not compared against `main`.
