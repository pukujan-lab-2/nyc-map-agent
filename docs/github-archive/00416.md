**Problem.** Someone who asks the map a question in Chinese, Spanish or Russian gets the answer in that language, but the buttons around it (Restroom, My train, Plan trip, Find exit), the ask bar, the answer card and the "Are you in the station?" prompt stay in English. For the newcomer this app is for, half the screen is still unreadable. The "Hey map" wake phrase also only listened in US English.

**What changes**

- The first screens have their own text in all eight app languages (English, Spanish, Chinese, Russian, Bengali, Haitian Creole, French, Korean).
- Which language the app shows, in order:

  | Order | Source |
  |---|---|
  | 1 | The language picked in the menu (the existing setting) |
  | 2 | The language of the last question, only when the text makes it clear: its script (Chinese, Korean, Russian, Bengali) or Spanish punctuation (¿ ¡ ñ) |
  | 3 | The browser's language |
  | 4 | English |

  The asked language is kept on this device only.
- "Hey map" listens in the app language and hears the phrase in each language ("oye mapa", "嘿地图", "эй карта", and others).
- The agent overlay's size budget goes from 22.2 kB to 22.6 kB: the eight-language text costs about 130 bytes over the old limit.

**How to verify**

- New browser test `e2e/app-language.spec.ts`: at 375×667 and 320×568, asking "我要上厕所" turns the ask bar, "More" and the four task buttons Chinese, and the buttons stay on screen.
- Typecheck, lint, all unit tests and all 30 browser tests pass locally; size budgets pass with the raise above.

**What stays the same**

- Answers were already in the question's language (server prompt); unchanged.
- Plain Latin-script questions don't switch the language, since they could be English, French, Haitian Creole or Spanish without accents.
- Not translated yet: the top menu row ("My day" and its dropdowns) and deeper panels.
