# Issue #604: Claude Code sessions here followed a week-old copy of the rules and a contradicting memory file, because nothing checks the checkout against GitHub

- State: open
- Opened by Pukujan on 2026-10-31
- Original: https://github.com/Pukujan-lab/nyc-map-agent/issues/604
- Labels: observational-issue, ontology:oio-1.1.0, ontology:project-1.0.0, proposal, relation:related, status:open, type:observational, account:agent-or-unmapped, needs-filer-stamp, needs-impact-evidence, needs-record-context, needs-release-relevance, priority:1

### Summary

From 2026-10-25 to 10-31, the main checkout (`~/Documents/projects/nyc-map-agent`) sat on `docs/project-realignment` (PR #378), about 201 commits behind `main`. 13 of 20 Claude Code sessions started there and read its old `AGENTS.md`, which lacks the startup steps, the worktree rule, the writing-rules step, the checkpoint step and the issue-shape rule, and its `.claude/settings.json` lacks the issue guard and hygiene hooks. A Claude memory file also told agents to make worktrees in `.worktrees/`, which the rules forbid. The two sessions started from an up-to-date `main` followed the rules. The fix is enforcement from the stack's guard hooks ([agent-stack-train#37](https://github.com/Pukujan/agent-stack-train/issues/37)), installed here, plus correcting the memory file.

### Acceptance Criteria

1. This repository carries the stack's guard: `.claude/hooks/acs_guard.py` and its SessionStart, PreToolUse and Stop hooks in `.claude/settings.json`, installed by `acs_install.py` from a certified stack commit.

3. CI fails when either is missing (`hotload_check`, and `check-adopter` with `claude: require`), and fails a pull request that names no owning issue.
4. A Claude Code session here is blocked when it commits without an owning issue, pushes to `main`, makes a worktree inside the checkout, or stops with unpushed or uncheckpointed work.

### Symptoms

1. **Old rules read as current.** 13 of 20 sessions loaded the 4.3 KB `AGENTS.md` from `docs/project-realignment` instead of `main`'s.
2. **Worktrees inside the repository.** `git worktree add .worktrees/video`, `.worktrees/voice-noisy-room`, `.worktrees/motis-planner` and `.worktrees/place-readback` (sessions 133c8137, 0dc0bcae, 0b7a5835).
3. **Memory file contradicts the rules.** `feedback-clean-machine.md` says "worktrees only under .worktrees/"; the next command after reading it created one.
4. **Issue log in prose.** #594 was filed with hand-written headings, not through `issue_log_shape.py`, and got `needs-*` labels.
5. **Unmerged branch deployed.** 0dc0bcae checked out unmerged `feat/motis-planner` on the live VPS and redeployed with `git pull`; the owner asked "is github not the authoratative".
6. **Pushes straight to main.** 133c8137 ran `git push origin HEAD:main` four times after a one-off "skip pr" go-ahead.

### Hypotheses (unverified)

- **H1: text loses to Claude Code's built-in defaults.** Status: confirmed in the audit for octo-database; inferred here. Would confirm: breaks stop once the guard blocks them. Would refute: the same breaks recur with the guard installed. Experiment: run one sample task with the guard installed and count blocked actions.
- **H2: stale or missing local rules.** Status: confirmed where sessions started on a branch without the current `AGENTS.md`. Would refute: sessions on an up-to-date `main` break the rules at the same rate.

### Counter-signal

Sessions that started from an up-to-date `main` with the rules loaded followed most of them, so text alone works some of the time. The guard must not block work that already follows the rules.

### Honest Caveat

The audit read Claude Code transcripts on one Mac. The desktop app's own instructions are not stored in transcripts, so their share of the breaks is inferred from timing and wording. Codex sessions were not measured.

### Problems vs Gaps

- Problem: agents break the PR, checkpoint, worktree and issue-log rules in Claude Code (symptoms above).
- Gap: nothing installed here enforces the rules; they are text only.

### Proposal *(proposal)*

Nothing here exists yet in this repository. Install the stack's guard and bridge through the train's upgrade pull request, then require them in CI.
