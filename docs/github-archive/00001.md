### 2. Single-source vs Average view
- `src/lib/datasets/view.ts` and `composite.ts` re-score the map for a single source, or for **Average**: a percentile rank (0–100) per area for each ticked source, then the mean.
- The legend lists the contributing sources. The details sheet shows each source's raw count and percentile.
- State is kept in the URL: `view`, `sources`, `avg`.

### 2b. Direction (polarity) for the Concern score (follow-up commit)
- Every registry entry has a default `polarity`:
  - `worse` (higher is worse): 311, noise, crashes, HPD violations.
  - `better` (higher is better): trees, ramps, speed humps, SIP corridors and intersections, PLUTO residential units.
- The Average view is now the **Concern score**. Each "better" source contributes `100 − percentile`, so a higher score always means more concern.
- In the data-sources drawer, each source in the average has a small "higher is better / higher is worse" button that flips its direction. Flips are kept in the URL as `flip=<ids>`.
- The legend says "Concern score" and marks each contributor ↑/↓. The details breakdown shows each source's direction, raw percentile and concern contribution.
- New unit tests cover the default polarities, the flip logic, inversion in the composite, and the direction passing through `applyView` and the URL parser.

### 3. UX (shadcn)
- New **data-sources drawer** (Sheet + Accordion by category), with a Switch to load each source and a Checkbox for "in average".
- New **view-mode DropdownMenu**, which replaces the layer pill in the dock and the settings drawer.
- The **details sheet** is now Accordion sections: view breakdown, noise/crashes/timeline tabs, all loaded sources, walking directions.
- Added the standard shadcn `accordion`, `collapsible`, `dropdown-menu`, `switch`, `checkbox` and `label` files.

### 4. Street view
- Both `VITE_MAPILLARY_TOKEN` and `MAPILLARY_TOKEN` work, via `envPrefix: ["VITE_", "MAPILLARY_"]`. Server-only names like `INFERHUB_API_KEY` match neither prefix.
- The nearest-photo search tries 250 m, then 750 m, then 1500 m. A photo found further out is labelled, e.g. "widened the search to 750 m; this photo is 640 m away". The no-photo message names every radius it tried.
- Still uses the official `mapillary-js` Viewer.
- ⚠️ I could not test this live because there was no Mapillary token.

### 5. Walk camera and directions
- **Blur fix:** walking now uses pitch 75° and zoom 18.5, with scroll-zoom clamped to 16.5–19. The old pitch 85° / zoom 21 rendered tiles far past their native zoom. Map clicks now work while walking.
- **Walking directions** (`src/lib/api/routing.ts`): a plain `fetch` to the public OSRM foot profile at `routing.openstreetmap.de/routed-foot`; override with `VITE_OSRM_URL`. You set A/B from the dock's navigation button, or "Route from/to here" in the details sheet. The route is drawn as a MapLibre line with A/B dots, and the card shows distance and time.
- **Walk along route** drives the street camera along the polyline. `poseAlongRoute` is unit-tested.
- **Usage-policy caveat:** the FOSSGIS server is a donated community service. Its policy (https://routing.openstreetmap.de/about.html) asks for light, non-bulk use and OSM attribution. The app sends one request per A/B pick and shows the attribution. Self-host OSRM for real traffic.

### Also fixed (both were already broken on `main`)
- `applyAtmosphere` called `map.setFog`, which maplibre-gl 4.7 doesn't have. It failed `tsc`, so `pnpm build` was red on main, and it threw at runtime. It now uses MapLibre's `setSky`.
- Two `walk.test.ts` cases assumed a 1 s frame, but `stepPose` clamps frames to 0.2 s. I fixed the tests.
