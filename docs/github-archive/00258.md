Closes #252.

**Root cause of cut-offs**
1. `SpeechRecognition.continuous = false`: Chrome ends the session at the first short pause, cutting the user off mid-sentence; words still marked interim were dropped.
2. The whole answer was one `SpeechSynthesisUtterance`: Chrome stops long utterances (~15 s), can GC an utterance (no onend), and the first answer could start before voices loaded.
3. No barge-in, and the full text answer was read aloud.

**Changes**
- `useSpeech`: continuous recognition + 1.3 s silence window ends the turn; interim tail kept; recognition aborted before TTS.
- `lib/voice/tts.ts`: sentence chunking, queue, 10 s pause/resume keep-alive, bounded voiceschanged wait, utterance held against GC, `spokenSummary` (short spoken answer, details on screen).
- `lib/voice/bargeIn.ts`: hands-free only; echo-cancelled getUserMedia + RMS detector; talking over the answer stops TTS and listening resumes. In-memory, nothing recorded; mic released immediately.
- Status: Listening (live transcript) / Thinking… / Speaking (talk to interrupt).
- Context: prior turns + shared location + street-view spot sent each voice turn (verified in e2e).
- Tests: unit tests (chunking, summary, voice pick, voices race, cancel, VAD); e2e has a mid-sentence pause that must not end the turn.
