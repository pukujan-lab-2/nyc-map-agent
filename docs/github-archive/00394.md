On 2026-10-24 this laptop had 46 git worktrees for this repo and about ten dev servers that had been running for one to three days. The ACS (Agent Custom Setup) hot-loader is meant to prevent that. It was installed here on 2026-10-21, but its install only writes state files. No agent was ever told the rules: check in to the coordination seat, update `checkpoints/CURRENT.md`, keep worktrees in `~/.cache/acs/`, stop your servers. Nobody did any of them for three days. The full investigation is in Pukujan/agent-custom-setup#112.

## What changes

- `AGENTS.md` gains an `acs:boot` block with the start, during and end steps every agent follows: Claude Code, Codex, Grok, or a person.
- `CLAUDE.md` is new and imports `AGENTS.md`, so Claude Code sees the same rules.
- `.claude/settings.json` adds a session-start hook. It runs `scripts/agent-hygiene.sh --yes`, which stops this repo's dev servers and test browsers once they've run for more than six hours, then reports what ACS's `dev_root_check.py` would tidy. It only looks at programs (node with vite, playwright or tsx, esbuild, headless Chromium) whose working folder is this repo or one of its worktrees. Other projects are never touched.
- `.gitignore` ignores `.claude/worktrees/` and `.claude/settings.local.json`.

## How to verify

1. `bash scripts/agent-hygiene.sh` lists the leftover processes it would stop, without stopping them.
2. `AGENT_HYGIENE_MAX_AGE_MIN=1 bash scripts/agent-hygiene.sh` shows today's running servers being picked up. Agents whose prompt mentions vite are not matched.
3. `python3 .coord/bin/seat_protocol.py status` works from the repo root.

## What stays the same

No app code changes. The watchdog workflow from the ACS pack is not added, because it would run on the single self-hosted runner every 10 minutes and needs the owner's call. The stale boss seat (held by `grokbot-skyline@box` since 2026-10-21) is left for the owner to clear.
