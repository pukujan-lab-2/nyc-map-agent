# Issue #199: Voice: restore a labelled entry point, add no-model fallback intents, fix /api/agent 400 and scope

- State: closed (2026-10-25)
- Opened by Pukujan on 2026-10-21
- Original: https://github.com/Pukujan-lab/nyc-map-agent/issues/199

## Problem

The voice and text assistant from #111 (issue #84) is still in the app, but nobody can talk to it, and when the model fails it says nothing useful. Alex wants a hands-free, "talk like Siri" mode that still answers core questions with no language model.

## Symptoms

1. **No voice entry point.** Since the Layout A redesign (#173), the top bar only has **Ask**. The microphone is a small icon inside the Ask sheet, so voice is out of sight.
2. **Every real assistant call fails with 400.** `POST /api/agent` passes `c.req.raw` to the handler after the OpenAPI validator has already read the body, so `request.json()` fails and the handler answers `bad_request`. Unit tests call the handler directly, so they never saw it.
3. **Unknown model id.** The default `deepseek/deepseek-v4.1-flash` now returns `model_not_found` from InferHub (the LLM gateway). Ids need a provider prefix, for example `cb/deepseek-v4.1-flash`.
4. **No answer without the model.** When the key or the model fails, the reply is "The model call failed." There is no fallback for next train, line status, restroom, weather, directions or "follow the train".
5. **Scope and cost are open.** The system prompt does not limit topics, output length is not capped, tool rounds go up to 8, and there is no per-IP rate limit.

## Hypotheses

- **H1: the body is read twice.** Status: **confirmed**. Would confirm: a local server returns `{"error":"bad_request"}` for a valid body. Would refute: a 200 stream. Experiment: curl the route on a local server. Result: 400 before the fix, a streamed answer after it.
- **H2: the model id is stale.** Status: **confirmed**. Experiment: a chat completion with the old id returns `model_not_found`, and with `cb/deepseek-v4.1-flash` it returns 200.

## Proposal *(proposal)*

- Add a labelled **Voice** button next to Ask: tap to listen, tap again (**Stop listening**) to stop. Add an optional **Hands-free** toggle in the assistant's menu.
- Add a deterministic intent layer that needs no model and answers from the app's own feeds.
- Fix the route and the model id. Restrict the system prompt to getting around NYC and this app's features. Cap output tokens and tool steps, and add a per-IP rate limit.
- Add an eval of 15 off-topic and prompt-injection prompts that must be refused.

Refs #84

**Pukujan commented, 2026-10-25**

All five parts are now on main:
1. Voice entry point: the mic and the hands-free button sit on the Ask bar.
2. The 400 and 3. the model id were fixed earlier.
4. No-model answers: #440 answers restroom and line-status questions straight from the restroom list and the live MTA feed when the daily budget is spent or the model fails.
5. Scope and cost: #434 caps answers at 800 output tokens and adds a scope rule the agent keeps even when a tool result tells it otherwise, with a test. The per-address limit and daily budget were already in place, and #438 adds a limit on every API call.
