# PR #211: ci(db): migrations up/down/up on a throwaway Postgres, fail on schema drift

- State: merged (2026-10-22)
- Opened by Pukujan on 2026-10-21
- Original: https://github.com/Pukujan-lab/nyc-map-agent/pull/211
- Labels: type:ci, area:db, area:ci
- Branch `ci/migration-roundtrip` into `main`, +121 −0 in 5 files, merge commit 344e0e8707f169c4c1eeec23fcf7986f5579c7b3

Down migrations were never exercised, so a broken rollback or an `up` that does not reproduce the same schema would only surface during an incident.

**What changes**
- New `migrations` job in `ci.yml` (gravebuster runner): a throwaway `postgres:16.4` service container, [dbmate](https://github.com/amacneil/dbmate) 2.28.0 (MIT, the tool `scripts/migrate.ts` already mirrors) downloaded with a pinned SHA-256.
- `scripts/ci/migration-roundtrip.sh`: baseline → up → down to zero → up. Fails if the schema after all downs differs from the baseline, or the second up differs from the first.
- `db/ci/schema-snapshot.sql`: deterministic catalog snapshot (tables, columns, defaults, indexes, constraints, view bodies, functions, triggers).
- `db/ci/legacy-public-tables.sql`: empty copies of the `public.nyc_*` tables that predate the migrations (columns from `scripts/ingest.ts`).
- Fix found by the check: the first migration's down left the `raw`/`core`/`marts` schemas behind; it now drops them (no CASCADE).

**Verify:** locally against Postgres 16.4: `migration round trip OK: 7 migrations, 282 schema objects, no drift`.

**Unchanged:** the production migrator (`pnpm db:migrate` via Octo) and every up section.

**Branch protection:** `migrations` is not yet a required check; add it after this merges.

Closes #206
