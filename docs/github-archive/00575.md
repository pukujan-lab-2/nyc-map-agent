**Problem:** "which exit for the Met?" and "how do I get to Grand Central?" have one answer the app's own tools already compute (the exit finder and the transit planner), yet each waits on a model round trip that is slow on the live site and can fail. #573 did this for restrooms and line status; this adds exits and two-ended trips.

**What changes** (`server/features/agent/noModel.ts`, `routes.ts`)
- **Exit:** "which/what exit (should I take) (at STATION) for/to PLACE". Calls `station_exit` and answers "Use the NE exit at 42 St-Bryant Pk, then about 4 min on foot. Want to start?", the shape the prompt asks of the model. No station means the one you are at, and needs your location.
- **Trip:** "how do I get / Plan a trip / directions (from A) to B". Calls `transit_plan`, then `showRoute` and `openPanel` like the model does, and answers with the lines, minutes, arrival time, the exit advice, and a trip-breaking change first when there is one. Only when the mode chip is transit.
- **Still the model:** any time ("at 5pm", "tomorrow"), way to travel ("by bus"), extra wish ("with a stroller", "and then"), a comma or question inside, no destination (the Find exit button's own question), a place the lookup cannot find, or a trip the day's changes block.

**How to verify:** unit tests for what matches and what does not; all 227 agent tests pass. After deploy, the live `/api/agent` is asked an exit and a trip question.

**Unchanged:** other languages, the budget fallback, every other question.
