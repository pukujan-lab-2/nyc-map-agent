The chat agent had no rate limits (none found on `main`), so tabs left open, spam or heavy use could run up model costs for an open-source project.

## What changes
- Per-client limits on `/api/agent`, keyed by `CF-Connecting-IP` first (Caddy replaces `X-Forwarded-For` with the tunnel's address, so that is only a fallback). Defaults: `AGENT_RATE_WINDOW_MAX=20` per `AGENT_RATE_WINDOW_HOURS=3` (each question frees 3 h after use) and `AGENT_RATE_BURST_MAX=5` per `AGENT_RATE_BURST_SECONDS=60`; 0 turns a limit off. Malformed or refused requests do not count.
- When limited: HTTP 429 with `Retry-After` and a JSON body; the message says when the next question frees up (New York time) and that the map and restrooms still work, and never mentions payment. `src/features/agent/stream.ts` shows this message (one line).
- Daily budget by reported tokens per UTC day: past `AGENT_DAILY_TOKEN_CAP=3000000` it uses `AGENT_CAP_MODEL` with no fallbacks, or answers without a model if unset; past `AGENT_DAILY_TOKEN_HARD_CAP=4000000` it always answers without a model. **The 3M and 4M defaults are guesses for the owner to set.**
- `.env.example`, `server/openapi.ts` and `openapi.json` updated.
