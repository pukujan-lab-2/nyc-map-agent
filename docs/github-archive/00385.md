Answers gave no sign of how fresh their data was, the agent could state numbers no tool returned, and its instructions didn't know the product's goals or the available data.

## What changes
- Every data tool result carries `source`, `asOf` and a stale flag; the stream sends a `sources` line, and `AnswerSources.tsx` shows "Sources · MTA service alerts, updated 40 s ago" with stale data marked "(may be out of date)". Thresholds: MTA alerts 2 min, daily datasets 3 days, elevators 10 min, traffic and 511NY 15 min, weather warnings 30 min, forecast 3 h, restrooms 180 days (the last five chosen by the agent; please confirm).
- The server flags figures in a reply when no data tool returned anything (tested with an invented "312 noise complaints"); when tools did run, only prompt rules apply.
- The prompt moved to `server/features/agent/prompt.ts` and was rewritten around the product's uses; the live-feed and layer lists are generated from the source table and dataset registry, and a test checks every tool it names exists.
- New `line_status` tool (live subway alerts and skipped stops). `context/CHAT_TOOLS.md` updated.
