# PR #172: Readable transit map on phones: pale streets, place icons off by default

On a phone the subway and bus lines were hard to pick out: coloured streets with dark casings, every minor street name and hundreds of place icons competed with them.

**What changes**
- On phones (under 1024 px wide) and whenever Transit Focus is on, streets are drawn plain and very pale with no casings; minor street names, path names, one-way arrows and road shields are hidden. Major street names stay, faint but legible. All of it is paint and layout properties on the basemap's own MapLibre layers, and the originals are restored exactly when it turns off.
- Place icons (shops, cafés, churches…) are hidden by default. A labelled Places chip brings them back; the choice is saved in the browser.
- Bug found while checking: one tile or data-source error while the style was still loading (a slow phone, the areas API failing) swapped the whole map to the raster fallback, which looks busy and cannot be restyled. The fallback now happens only when the style itself fails to load.
- Transit Focus state moved to shared map code so the map and the transit layer read the same switch.

**How to verify**
Open the app at 390 wide around Herald Square: streets are pale, minor names and place icons are gone, transit lines stand out. At 1440 the full basemap shows unless Transit Focus is on. Before and after screenshots at both widths were taken over the browser debugging protocol and reviewed. Eight new unit tests cover which layers change and the saved places choice.

**What stays the same**
No new dependency; desktop default look unchanged. Typecheck, lint, unit tests and full project-continuity and content-generation checks pass.
