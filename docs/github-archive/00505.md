**Problem:** asked in Nepali ("टाइम स्क्वायर कसरी जानी हो"), the assistant wrote back in Nepali, but the spoken answer was not Nepali. There were two causes:
- **Not recognised from speech:** the speech-to-text step didn't know Nepali, so the voice fell back to the app's English.
- **No Nepali voice:** browsers on Mac and most phones have no Nepali voice at all, so the English voice tried to read Devanagari.

**What changes**
- Speech-to-text recognises Nepali, plus Marathi, Punjabi, Tagalog, Greek, Persian and Tibetan.
- The spoken voice follows the script the answer is written in. When the language has no voice, or the text is in a script the chosen language doesn't use, a voice that reads that script is borrowed. Hindi reads Nepali and Marathi, which share Devanagari. The same rule covers Bengali, Arabic, Korean, Chinese and Cyrillic text.

**How to verify:** ask in Nepali by voice or text. The answer is spoken in a Hindi voice reading the Nepali text, not the English voice. Unit tests are `voiceFor` in `src/lib/voice/tts.test.ts` and `detectedLang` in the speech-to-text tests.

**What stays unchanged:** English, and any language with its own voice on the device.

**Caveat:** a Hindi voice reading Nepali is close but not native. A true Nepali voice would need a server-side text-to-speech service.
