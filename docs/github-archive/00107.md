Live MTA transit as a feature module (`src/features/transit`, `server/features/transit`), toggled from the Layers dropdown under **Transit** (Subway / LIRR / Metro-North / Buses) plus a **Transit** panel chip.

**Feeds (server proxy, ~15 s in-memory cache, decoded with `gtfs-realtime-bindings`)**
- Subway: `api-endpoint.mta.info/Dataservice/mtagtfsfeeds/nyct%2Fgtfs`, `-ace`, `-bdfm`, `-g`, `-jz`, `-nqrw`, `-l`, `-si` → `/api/transit/subway`
- LIRR `lirr%2Fgtfs-lirr` → `/api/transit/lirr`; Metro-North `mnr%2Fgtfs-mnr` → `/api/transit/mnr`
- Buses: `gtfsrt.prod.obanyc.com/vehiclePositions` with server-only `MTA_BUSTIME_KEY` → `/api/transit/bus`; `/api/transit` reports `{bus}` and the Buses toggle is hidden without the key
- Alerts `camsys%2Fall-alerts.json` (Mercury `alert_type`) + elevator/escalator `nyct%2Fnyct_ene.json` joined to `nyct%2Fnyct_ene_equipments.json` → `/api/transit/alerts`
- PATH: not included. I found no reliable public PATH GTFS-rt feed.

**Static data:** `pnpm build:transit` bakes the MTA static GTFS (`rrgtfsfeeds.s3.amazonaws.com/gtfs_subway.zip`, `gtfslirr.zip`, `gtfsmnr.zip`) into `public/transit/*.json`: route shapes in official colours, stations, one measured shape per route, subway entrances (data.ny.gov `i9wp-a4ja`). Each shape segment gets a grade (underground / at grade / elevated) from OSM railway `tunnel`/`bridge`/`layer` tags via Overpass. That data is © OpenStreetMap contributors, ODbL.

**Map:** react-map-gl `Source`/`Layer` (MapLibre).
- Tracks come from the GTFS shapes. Underground runs are a faint dashed ground line. Elevated subway runs get a route-coloured viaduct deck on piers in 3D. LIRR and Metro-North run at grade.
- `trackHeightProfile(sys, route)` gives the height of each vertex. It ramps at no more than 3.5% from tunnel portals up to the Manhattan Bridge (B D N Q, 40 m), the Williamsburg Bridge (J M Z, 38 m) and the 1 train's Manhattan Valley Viaduct (16 m). No generic viaduct is drawn on the bridges, so the bridge models can align with the profile.
- Stations and planned-work wrenches. Reroutes and skipped stops are drawn on the exact segment, with an amber ring on each affected stop. Stations with an elevator or escalator outage get an accessibility marker. Entrances show at street level.
- Vehicles in 2D are oriented arrows. In 3D they are instanced three.js bodies in ONE shared custom layer (`src/lib/map/threeLayer.ts`, lazy) that ride their height profile. Underground trains are translucent ghosts and are hidden at street level. Vehicles are tweened, culled to the viewport and capped at 400.

**Panel (usePanel):** station card with next arrivals by line and direction, outages (what is out, the reason, when it is back, whether the station is still step-free) and planned work. Vehicle card with line, direction, next stop, ETA and **Follow** (camera eases on each update; drag or Esc exits). Service status has Starred countdowns ticking every second, a browser-notification toggle, Planned work and an Accessibility filter. Starred stations and lines are kept in localStorage. sonner shows notices for starred lines. Station search is registered with `usePanelSearch`.

**Deps:** `gtfs-realtime-bindings` 1.1.1 (Apache-2.0, MTA's official bindings). `three` was already on main. AI_RULES.md now states that three.js is approved in one shared MapLibre custom layer and that deck.gl stays banned. size-limit lines are added for the lazy transit chunk and threeLayer.

**Not in this PR (follow-ups):** Sketchfab glTF models (downloads need an authenticated Sketchfab account, so vehicles are procedural low-poly instanced bodies tinted per line), procedural el bays and station canopies, a 3D entrance kit, the station x-ray view, and Mini Tokyo 3D (studied, no code copied).
