### Summary

Komodo now deploys main to the VPS, but nyc.design-bakery.com still answers 530 because no Cloudflare tunnel routes that name to the app. CI's live contract check stays off until the route works and the `NYC_PUBLIC_URL` repository variable is set.

### Identity and Lineage

Repository Pukujan-lab/nyc-map-agent, host `vps`. Follows #611 (deploy script, merged in #613) and Pukujan-lab/server-management#69 (Komodo stack and action). The route goes on Cloudflare tunnel A (`octo-cloudflared` on the Docker network `study-os_edge`).

### Acceptance Criteria

1. Tunnel A has a public hostname nyc.design-bakery.com pointing at `http://nyc-map-web:8080`.
2. `curl -s -o /dev/null -w '%{http_code}' https://nyc.design-bakery.com/healthz` prints 200.
3. The repository variable `NYC_PUBLIC_URL` is `https://nyc.design-bakery.com`, and CI's contract job runs on the next merge.

### Boundaries and Next Action

In scope: the Cloudflare public hostname (owner's dashboard), the repository variable, and the checkpoint line. Out of scope: the deploy path, which already works. Next action: the owner adds the hostname on tunnel A.

### Symptoms

1. **Name does not answer:** nyc.design-bakery.com returns 530 (Cloudflare has no route for it).
2. **Contract check skipped:** CI's contract job is skipped while `NYC_PUBLIC_URL` is unset.

### Hypotheses (unverified)

H1. Adding the hostname on tunnel A is enough, because the app already sits on the tunnel's network. **Status:** unverified. **Would confirm:** `/healthz` on the public name answers 200 right after the route is added. **Would refute:** it still answers 530 or 502. **Experiment:** add the route, then curl the public name.

### Counter-signal

From a container on `study-os_edge`, `http://nyc-map-web:8080/healthz` answered 200 on 2026-11-01, so the tunnel can reach the app once the name exists.

### Honest Caveat

Cloudflare's dashboard was not opened; the 530 comes from earlier curl checks, and the route list is the owner's to change.

### Problems vs Gaps

Problem: riders cannot reach the live app by its name. Gap: no public hostname on tunnel A, and `NYC_PUBLIC_URL` unset.

1. Tunnel A (`5b33f769…`, run by `octo-cloudflared` on the VPS) gained the rule `nyc.design-bakery.com → http://nyc-map-web:8080`, placed before the catch-all 404. Its earlier config is saved locally; the other seven rules are unchanged. The tunnel logged the new config as version 5.
2. The CNAME `nyc.design-bakery.com` now points at `5b33f769-….cfargotunnel.com`, the same target as acs.design-bakery.com. It is still proxied.

acs, octodb, umami and voidfeed still answer 200. The gravebuster tunnel's own config was left alone.

**Not done yet: `NYC_PUBLIC_URL`.** Running CI's contract check against the live site found one server error: `GET /api/v1/ferry` returns 502, because the ferry layer still calls an OpenTripPlanner that does not exist on the VPS (#618). Setting the variable now would turn main red on every merge, so it waits for #618.
