# PR #189: Navigation arrows: glowing route, chevrons, turn arrow and Navigate mode

**Problem.** Following walking directions in street view was guesswork: only a thin line, no direction, no next turn, no distance. This adds navigation arrows (phase 1 of 3 of Live View).

**What changes** (all in a new module `src/features/liveview/`, mounted as a feature overlay; no edits to MapView, street-view camera code, the drawer or TransitLayer):
- **Street view:** the route as a glowing ribbon (wide blurred `line-blur` line under a crisp core), the walked part dimmed, chevrons along it (`symbol-placement: line`, map-pitched), a big turn arrow lying on the ground at the next maneuver, and a compact card: "Turn left on W 42 St, 80 m" plus miles to go. It advances as the camera moves (route projection, a maneuver counts as reached within 5 m).
- **2D Navigate mode:** a labeled "Navigate" button; heading-up camera tilted 55°, a chevron puck with a translucent halo sized to GPS accuracy, a "Recenter" button after you pan, "Location accuracy: about N m", and "Stop navigation".
- **Router:** the existing FOSSGIS OSRM foot profile (`src/lib/api/routing.ts`, same server the agent's `route_walk` uses), asked again with `steps=true`. No new routing provider.
- **Colours:** read from CSS variables `--nav-route`, `--nav-glow`, `--nav-ink`, falling back to `--primary` / `--primary-foreground`, and repainted when the `<html>` theme class changes, so the coming Auto (time-of-day) theme can set them. Nothing else is coloured.
- The plain Directions line hides while the glowing one shows and comes back on exit.
- Bundle: the overlay is a lazy chunk (~5 kB brotli); the "all JS" budget goes 927 → 940 kB to leave room for phases 2-3.

**Privacy.** Location is requested only when you tap Navigate, is used in the tab only, never sent to our API, and the watch is cleared on stop, when the route is cleared and on unmount.

**How to verify.** Pick A and B, tap "Walk along route": chevrons, turn arrow and card appear. Outside street view tap "Navigate". `pnpm test` (new `steps.test.ts`: URL, wording, step advance), `pnpm lint`, `pnpm lint:boundaries`, `pnpm size`; PCM, CGM and ACS hotload gates pass.

**Screenshots (simulated, headless Chrome with SwiftShader; geolocation overridden for the 2D shot):** on the box at `/workspace/liveview-shots/p1-street-1440.png`, `p1-street-390.png`, `p1-nav2d-1440.png`.

**Known limits.** The street-name pill shows the OSRM step's street name; the basemap's road layers do not expose names to `queryRenderedFeatures`, so unnamed footway steps show no pill. Heading in 2D uses GPS course when moving, otherwise the route direction (no compass until phase 3).
