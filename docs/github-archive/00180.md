# Issue #180: Jump to a neighborhood selects it but doesn't move the map

- State: closed (2026-10-21)
- Opened by Pukujan on 2026-10-21
- Original: https://github.com/Pukujan-lab/nyc-map-agent/issues/180

Picking a neighborhood from **Layers & filters → Jump to a neighborhood** selects it and opens its details sheet, but the map stays where it was. If the neighborhood is off-screen, it looks like nothing happened.

## Symptoms
1. **Map does not move.** Choosing any neighborhood in the drawer's "Jump to a neighborhood" list leaves the camera in place.
2. **Search works.** Picking the same neighborhood from the search bar does move the map.

## Hypotheses
- **H1: the drawer handler never asks the map to move.** Status: confirmed. Would confirm: the drawer's `onValueChange` (the function run when the list choice changes) calls `selectNta` and `setDetailsExpanded` but not `flyTo` (the camera move). Would refute: a `flyTo` call or a selection-driven camera effect elsewhere. Experiment: read `src/components/ControlDrawer.tsx` and `src/components/MapView.tsx`; the search bar (`PanelSearch.tsx`) calls `flyTo` explicitly after `selectNta`, and the map only moves on `flyTo`.

## Evidence
- Same code on `main` and on the Layout A branch (pull request #173); #173 does not touch `ControlDrawer.tsx`, so the bug exists on both.
- A unit test of the drawer's jump logic with the old behaviour (no camera move) fails.

Caveat: verified by reading code and a unit test, not in a real browser.

## Proposal *(proposal)*
Have the drawer move the camera to the neighborhood's bounding-box centre, the same target the search bar uses, and share that target in one helper.
