Stacked on #210 (monotonic motion), which sits on #195.

- **Ingest:** `scripts/transit-observe.ts` + `.github/workflows/transit-observe.yml` run on the gravebuster runner every 15 min, polling the subway feeds every 30 s for 13 min. `SegmentObserver` records a stop's last predicted arrival/departure when the feed drops it: dwell = dep - arr, travel = arr(B) - dep(A). Stops dropped before they were due are skipped (reroutes/skips). Rows go to `raw.transit_segment_obs`; rows older than 60 days are deleted each run.
- **Rollup:** migration adds `marts.transit_segment_hourly` (median, p80, n by route, direction, station pair, kind, NY weekday and hour), refreshed by the job and by `db:refresh`. Plain Postgres. The job logs whether TimescaleDB is available in Octo so we can switch later; I couldn't check from outside CI because the Octo credentials only live in Actions secrets.
- **API:** `GET /api/transit-segments?route=G[&dow&hour]`, zod-typed query and response, in `server/openapi.ts` and `openapi.json`.
- **Interpolator:** `history.ts` blends the historical median with the live leg time (live weight 0.9 for legs starting now, down to 0.4 for legs 20 min out). The next stop's live ETA never moves, so the monotonic hold and shown ETAs stay on the feed. No history means live/schedule times as before.
- **Tests:** `observe.test.ts`, `history.test.ts`; typecheck, lint, boundaries and the gates script pass locally.
