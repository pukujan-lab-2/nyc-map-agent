# PR #343: fix(agent): retry when InferHub's market is busy and log the real error

Ask and trip planning on the live site intermittently answered "The model call failed." The key and model are fine: a direct call from the server works. When I ran the agent's own call inside the production container it failed once with InferHub's message "every provider within your price limit is busy or rate-limited right now", and the next call worked. Nothing in the app retried that, and the log only held a request id, so the cause was invisible.

## What changes
- `fallbackFetch` now retries the same model up to twice (0.6 s, then 1.2 s) when the answer is a 429 or the busy / rate-limited / price-limit message. This works with a single model, so it needs no new setting. If it is still busy it moves to the next fallback model, as before.
- The agent's error log now says the HTTP status and the provider's message (key-shaped text redacted), not just the request id.

## How to verify
- Unit tests cover: busy recognised by message or 429, retry then success with one model, give up after two retries and fall to the next model, and no retry on a 401. `server/features/agent` passes except `otp.test.ts`, which also fails on untouched `main` on this machine.
- Typecheck and lint pass. Not run against InferHub itself: the busy answer is intermittent, so the unit tests stand in for it.

## Unchanged
- The key, the default model, the status codes that already fell back (402, 5xx, model not found), and what the client sees on a final failure.
- Raising the key's max price in the InferHub dashboard, or setting `INFERHUB_MODEL_FALLBACKS` on gravebuster, is still worth doing and is not part of this PR.
