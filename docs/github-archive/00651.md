# Issue #651: Trips and multi-turn follow-ups fail silently: build a tool-sequence eval suite

- State: open
- Opened by Pukujan on 2026-11-01
- Original: https://github.com/Pukujan-lab/nyc-map-agent/issues/651

### Summary

The chat agent's trips, walks and multi-turn follow-ups fail in ways nothing measures: it answers the previous topic (a restroom for "get to Times Square"), plans a route in words without calling the planner or drawing it, treats "yes" as a new request, loops one tool eight times with an empty reply, and speaks internal names. Traces from 2026-11-01 show each. This builds a repeatable multi-turn suite that scores the tool sequence, the same way the line-status suite scores replies.

### Identity and Lineage

Repository Pukujan-lab/nyc-map-agent. Builds on #629/#630 (line-status eval) and `scripts/eval-trip-questions.ts` (#625). Overlaps the other agent's work on `fix/agent-sense` (`server/features/agent/turn.ts`, task NMA-0007), which this suite should measure. Related: #594, #641.

### Acceptance Criteria

1. `tsx scripts/eval-trips.ts` runs multi-turn scripts against the agent (in process or `--url`), several trials each, and prints a clean rate per check and per case.
2. Checks are pure and unit-tested offline, including the real failures seen in the traces.
3. Each row records model, prompt hash, tools hash and commit.
4. `docs/eval/trips/README.md` says how DeepSeek runs it with the existing loop (`docs/eval/line-status/PROGRAM.md`).
5. A baseline on LFM3 is recorded in the ledger.

### Boundaries and Next Action

In scope: the suite, its checks, its cases and its docs. Out of scope: changing the agent (the other agent's `fix/agent-sense`), the task classifier (next, on top of `turn.ts` once it merges), real rider questions (privacy documents first). Next action: build it, run a baseline.

### Symptoms

1. **Answers the last topic:** "get to times square" got the restroom answer again.
2. **Route in words only:** `transit_plan` ran but no `showRoute` or `openPanel`, so nothing is drawn and there is nothing to Play.
3. **Invented plan:** "Let me go to Brooklyn Bridge" got a route with no planner call.
4. **Yes misread:** "Yes, please" planned again and drew nothing.
5. **Tool loop:** a hunger question ran `suggest_layer` eight times and returned an empty reply.
6. **Internal names:** a reply told the rider to tap the "walkToNearest button for trip <id>".

### Hypotheses (unverified)

H1. These failures are the small model skipping steps in multi-turn context, not data errors. **Status:** unverified. **Would confirm:** the suite fails the same checks on LFM3 and passes them on a larger model with the same cases. **Would refute:** both fail alike. **Experiment:** run the suite on LFM3 and on DeepSeek.

### Counter-signal

On 10-31 a larger model (nemotron) completed `transit_plan`, `showRoute`, `openPanel` in order in the same app, which supports H1.

### Honest Caveat

The in-process run falls back to the built-in subway router when no planner is reachable, so trips differ from the live MOTIS ones; the checks look at tool use, not itinerary quality.

### Problems vs Gaps

Problem: multi-turn tool use fails silently. Gap: no suite scores tool sequences or multi-turn behavior.
