# Issue #363: Make a simple block map the default and the detailed 3D city optional

- State: closed (2026-10-25)
- Opened by Pukujan on 2026-10-24
- Original: https://github.com/Pukujan-lab/nyc-map-agent/issues/363

The detailed 3D city is heavy: the owner reports it does not run on many computers and slows their work computer. The realigned product needs a light map that answers questions, not a detailed city.

## What is needed
- The default map draws plain colored block shapes (MapLibre fill-extrusion of the existing tax-block tiles), only the route and data that answer the current question, and few labels. No three.js in this default.
- The detailed 3D city becomes an optional module, off by default, behind the flag registry's advanced tier. It is kept for later work, not deleted.
- Recognisable landmarks stay visible so people know where they are.
- Street level and Live View keep real detail (needed for the underground and exit problem).

## Evidence
- Owner's report and decision, 2026-10-23. The owner's reference is a simple dark block map with a route, noise and crash bars, a "heads up at this corner" callout and an "Agents working" panel.
- Tax-block tiles exist (`api/block-tiles.ts`, `scripts/build-block-tiles.ts`); the flag registry has basic and advanced tiers (`docs/ARCHITECTURE.md`).

## Hypothesis
**The detailed 3D city is the main GPU and memory cost.** Status: unverified. Would confirm: the baseline shows a large drop with the 3D city off. Would refute: no meaningful change. Experiment: compare the baseline with the module disabled.

## Acceptance criteria
- [ ] The default view loads no three.js code and no detailed building geometry.
- [ ] The 3D city can be turned on from advanced mode and is off by default.
- [ ] Landmarks remain visible in the default view.
- [ ] Measured against the baseline on the owner's phone and work computer.
