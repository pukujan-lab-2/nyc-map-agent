In the demo video the agent knows you're at a station and walks you out. Ours didn't know: if you asked "which exit?" while the underground helper was open, it answered as if you were anywhere. Event questions also failed whenever the first search found nothing.

## What changes

- **The agent knows where you are underground.** While the underground helper is open, each question carries the station name, whether you're riding or at the station, and the exit you picked. It is held in memory only and never stored. The agent names that exit by its streets and tells you to follow those signs.
- **Trips read like directions.** The agent gives the steps in order: walk and board, line and direction, where to get off, the exit and a landmark near it, the walk to the door. It ends by offering to start.
- **Every place answer says the way there.** Walks are now routes the map can draw. The restroom tool returns the walk to the nearest open one, so the answer gives the first turns and what it's next to, then asks "Want to start?". Yes draws the walk and opens its card. Landmark answers work the same way. The agent may only name landmarks the tools returned.
- **What to bring.** The trip's weather turns into a few words (umbrella, warm coat, water) only when it matters.
- **Event search tries harder.** It also answers "anything on at Bryant Park tomorrow?", which names a place rather than an event. It uses Tavily first, and TinyFish when Tavily has no key, fails or finds nothing. If the first query is empty it widens: the name in New York, then on Luma, Eventbrite, Meetup and Partiful, then the name alone.

## How to check

Open the underground helper at a station and ask "which exit?". Ask about a named event. `pnpm test` passes, along with typecheck and lint.

## Needs doing on the server

Add `TAVILY_API_KEY` to the production `.env`. Without it, search falls back to TinyFish as before.

## What stays the same

The model, rate limits, map tools and the exit screen are untouched.
