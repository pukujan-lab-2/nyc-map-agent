# PR #169: My location: share only on tap, exact position for directions, never kept

- State: merged (2026-10-21)
- Opened by Pukujan on 2026-10-21
- Original: https://github.com/Pukujan-lab/nyc-map-agent/pull/169
- Branch `feat/my-location` into `main`, +199 −30 in 9 files, merge commit 7f993a9f3d6cfe68d0a5e1d94ca7c03124cbedd5

Directions from "here" were less useful because the assistant only knew that a location existed, and the browser was asked for location the moment someone sent a question, without a clear choice.

**What changes**
- A My location button on the right rail. Only that tap asks the browser for permission; once sharing, the button reads Stop sharing location.
- The Ask panel shows whether location is shared, with Use my location and Stop sharing location buttons.
- The exact position is held in memory for this tab only (never in browser storage, cookies or the link) and goes to the assistant with each question while sharing, so it can plan from the right corner.
- The server uses it for that request only: it is not logged, not written to Octo or R2 storage, and the drive crash-hotspot lookup now leaves out the first 600 m of the route so no cell near the person reaches Octo.

**How to verify**
Tap My location: the browser asks, the map flies to you and the button changes to Stop sharing location; tap it and the next question is sent without a location. A new server test checks the model receives the exact coordinates while no log line or outbound call to Octo or R2 contains them; three client tests cover tap-only asking, stopping and refusal. The end-to-end trip test now taps My location first. Screenshots at 1440 and 390 wide were taken over the browser debugging protocol and reviewed.

**What stays the same**
No new dependency. Without sharing, "from here" questions get a request to say where you are starting. Typecheck, lint, unit tests and full project-continuity and content-generation checks pass.
