# Issue #618: The ferry layer is empty on the VPS because no OpenTripPlanner runs there

### Summary

On the VPS, `GET /api/v1/ferry` answers 502 `{"error":"upstream_error"}`, so the map has no ferry routes, terminals or boats. The route asks OpenTripPlanner (OTP) at `http://nyc-map-otp:8080`, and no OTP runs on the VPS: trip planning moved to MOTIS in #603, but the ferry layer was not moved with it.

### Identity and Lineage

Repository Pukujan-lab/nyc-map-agent, host `vps`. Code: `server/features/ferry/routes.ts` (`load()` posts a GraphQL query to `${OTP_URL}/otp/gtfs/v1`). Related: #603 (MOTIS replaced OTP for trips), #614 (public route; its CI contract check would fail on this endpoint).

### Acceptance Criteria

1. `curl https://nyc.design-bakery.com/api/v1/ferry` returns 200 with routes and terminals.
2. CI's contract command (Schemathesis against the public site, as in `.github/workflows/ci.yml`) reports no server errors.
3. The ferry layer shows routes on the live map.

### Boundaries and Next Action

In scope: where the ferry layer gets its data on the VPS. Out of scope: the trip planner, which already uses MOTIS. Next action: decide between reading ferries from MOTIS and running OTP on the VPS again.

### Symptoms

1. **Ferry endpoint fails:** `/api/v1/ferry` answers 502 on the VPS and on nyc.design-bakery.com.
2. **Fetch fails in the logs:** `nyc-map-web` logs `TypeError: fetch failed` at `ferry/routes.ts:76`.
3. **Contract check fails:** CI's Schemathesis run against the public site reports one server error, on this endpoint.

### Hypotheses (unverified)

H1. The endpoint fails only because no OTP service exists on the VPS. **Status:** unverified. **Would confirm:** pointing `OTP_URL` at a working OTP makes it answer 200. **Would refute:** it still fails with OTP reachable. **Experiment:** run the GraphQL query against any OTP with the NYC ferry feed.

### Counter-signal

`docker ps` on the VPS shows no OTP container and the env file sets no `OTP_URL`, so the default name `nyc-map-otp` cannot resolve. That supports H1 strongly but is not the experiment.

### Honest Caveat

Whether MOTIS can return ferry route shapes, stops and scheduled positions the way the OTP query does has not been checked.

### Problems vs Gaps

Problem: the ferry layer is empty on the live site. Gap: the VPS move did not carry over or replace the ferry layer's OTP dependency.
