## Problem

Words typed into the chat bar while the app was still loading could vanish. The page first shows a plain chat bar from `index.html` (added in #368), then swaps in the real one once the app's code has run. Keys typed during the swap arrived after the plain bar was removed, when no box had the cursor, so they were dropped.

The same race made browser tests in CI time out at random: they typed a question, the text vanished, and the Send button never appeared. That kept main red, so the freeze fix in #462 never deployed.

## What changes

- When the real chat bar replaces the plain one and the plain one had the cursor, the real bar now takes the cursor. Typed text was already copied across; now the keys still on their way land in the real bar too.
- A new browser test opens a walking route, presses **I'm lost**, and checks two things: the agent is asked exactly once, and the page still responds. With the #462 re-send loop put back, this test fails (the page freezes), so it now guards that bug.

## How to verify

- **The lost text:** a probe typed the moment the page loaded and checked that the words stayed. Before the fix it lost them in 1 of 12 runs; after the fix it kept them in all 30 runs.
- **The full browser test suite:** all 31 tests pass with retries off.
- **Unit tests:** all pass (1,255 tests). `shellDraft` gains a test for knowing when the plain bar holds the cursor.

## What stays the same

The plain bar's look, the copying of typed text, and the 30-second fallback removal are unchanged.
