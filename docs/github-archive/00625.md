# Issue #625: The trip chat guesses on vague requests instead of asking one question

- State: closed (2026-11-01)
- Opened by Pukujan on 2026-11-01
- Original: https://github.com/Pukujan-lab/nyc-map-agent/issues/625
- Labels: status:resolved

### Summary

Ask "I need to get to Brooklyn tomorrow" on nyc.design-bakery.com and the agent plans a trip to Brooklyn College leaving at 12:10 AM, without asking where in Brooklyn or what time. "Quiero ir a Brooklyn mañana con mi abuela" gets the same guess, in English, and nobody asks whether the grandmother needs step-free stations. The chat leaves the ask-or-plan decision to the model alone, and LFM3 (the open model that writes the replies) almost always plans.

Wanted: when a trip request is vague or missing something, the agent asks one short question first, in the rider's language. After it answers a trip, it offers one relevant follow-up ("Want the return trip?", "Need the step-free way?"). No confirmations and no read-backs: the owner rates this agent low stakes.

### Identity and Lineage

Repository Pukujan-lab/nyc-map-agent, live at nyc.design-bakery.com on the VPS. Code: the chat route `server/features/agent/routes.ts`, its rules in `server/features/agent/prompt.ts`, the trip tool in `server/features/agent/tools.ts`, the no-model fast path in `server/features/agent/noModel.ts`. The website copilot (Pukujan-lab/voice-agent-research) already asks clarifying questions; this ports the idea, without its confirmations.

### Acceptance Criteria

1. A vague trip request (destination is a whole borough, a time with no hour, an access hint such as "with my grandma" or "bad knee", unclear walking or mode) gets exactly one short clarifying question and no trip is planned that turn.
2. A complete request ("Union Square to Grand Central now") is planned with no question.
3. A planned trip ends with one follow-up offer picked in code from the trip: step-free way, fewer transfers, or the return trip.
4. This works in any language the rider writes in: the model reads the details, code decides.
5. Automated tests cover 1-3.
6. Deployed to nyc.design-bakery.com.

### Boundaries and Next Action

In scope: the trip request path (model route and fast path), the transit_plan tool's arguments and result, the prompt rule for asking. Out of scope: read-backs and confirmations, drive and walk planning, a step-free route search (the planners have no wheelchair option wired yet). Next action: add the slot check to transit_plan.

### Symptoms

1. **Broad place guessed:** "I need to get to Brooklyn tomorrow" planned a trip to Brooklyn College, leaving 12:10 AM.
2. **Access hint ignored:** "Quiero ir a Brooklyn mañana con mi abuela" planned the 5 train to Brooklyn College with no step-free question; the reply came back in English.
3. **No follow-up:** every trip answer ends "Want to start?" only, never the return trip or the step-free way.

### Hypotheses (unverified)

H1. The prompt's "ask one short question" rule is too weak for LFM3, which prefers to call transit_plan with defaults. **Status:** unverified. **Would confirm:** the same requests ask a question once code returns an ask from transit_plan. **Would refute:** LFM3 plans anyway after the tool says to ask. **Experiment:** rerun the three requests above after the change.

### Counter-signal

The Brooklyn request did call transit_plan, so the model reads the trip; it just never treated "Brooklyn" or "tomorrow" as too vague.

### Honest Caveat

Which details count as vague is a judgment the model still makes when it fills the tool's arguments; code checks those arguments plus a list of borough names. A model that marks a vague request as clear will still plan it.

### Problems vs Gaps

Problem: vague trips are planned on a guess. Gap: no code path makes the agent ask, and no follow-up offer exists.

**Before**

> Rider: I need to get to Brooklyn tomorrow
> Agent: Here's your trip to Brooklyn College … departing around 12:10 AM tomorrow … Want to start?

> Rider: Quiero ir a Brooklyn mañana con mi abuela

**After**

> Rider: I need to get to Brooklyn tomorrow
> Agent: Where in Brooklyn are you going? A street, a station or a place is enough.

> Rider: Quiero ir a Brooklyn mañana con mi abuela
> Agent: ¿A qué parte de Brooklyn vas? Basta con una calle, una estación o un lugar.

> Rider: 我明天要去皇后区
> Agent: 你要去Queens的哪里？说一条街、一个车站或一个地方就行。

> Rider: Get me to Grand Central now
> Agent: (the trip, then) Want the return trip?

**Still rough**
- A French message got the question in English: the model did not name the language, so the app fell back to English. Chinese, Spanish and the other app languages work.
- A soft hint such as "she walks slowly" can still be read as no hint by LFM3. The borough, missing start and vague-hour checks run in code and always hold.
- The live eval (`scripts/eval-trip-questions.ts --url ...`) trips the per-address rate limit when run in a burst; run it a few cases at a time.
