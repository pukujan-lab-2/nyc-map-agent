**Problem.** After #416, someone who asks the map in Chinese sees Chinese task buttons and a Chinese ask bar, but the menu row at the top (My day, Layers, Filters, Data, City data, Settings) and every dropdown under it stay in English. So a newcomer who can't read English still can't find the language setting, turn on restrooms, or read their own day.

**What changes**

- The menu row and all six dropdowns use the same app language as the rest of the app, in all eight languages (English, Spanish, Chinese, Russian, Bengali, Haitian Creole, French, Korean). That covers the menu names, the switches and choices, the Data dropdown (what's remembered, "Delete everything") and My day's section names and empty messages.
- The words live in their own dictionary (`src/lib/i18n/menuText.ts`), so the lazily loaded agent overlay doesn't get bigger.
- The "all JS" size budget goes from 1015 kB to 1020 kB, about 4 kB for the eight languages' menu text. The first-load and overlay budgets are unchanged and still pass.

**How to verify**

- `e2e/app-language.spec.ts` now also checks that after asking "我要上厕所", the menu pill reads 我的一天, and the Settings dropdown opens as 设置 with 语言 visible and fits on screen, at 375×667 and 320×568. Screenshots at 320 wide show the dropdown scrolling inside the screen with the map and task buttons still visible.
- Locally: typecheck, lint and all unit tests pass (1147 tests). The browser suite passes except two tests that failed once on a heavily loaded machine and passed on a rerun (the street-level mini map and the smart-mode trip card). The language test's first wait got a longer timeout for the same reason.

**What stays the same**

- English is still the default, and the order for picking a language is unchanged: the menu pick, then the language you ask in, then the browser's.
- Not translated yet: theme names (Ivory, Ink and so on), live notice text from MTA, and deeper panels such as the layers drawer and the line panel.
