Closes #625

## What changes

- `transit_plan` takes what the rider said as fixed values the model fills in any language: `timing`, `access`, `walking`, `mode` and `language`. Code in `server/features/agent/ask.ts` decides whether to ask or plan: a borough-wide place, no start while the location is unknown, a day with no hour, or an unclear hint (a grandmother, a bad knee, "not too far") returns one question instead of a trip. After two answers in a row it plans with defaults, so it cannot loop.
- The app says the question and the closing offer itself, from phrases in the eight languages the app speaks (English, Spanish, Chinese, Russian, Bengali, Haitian Creole, French, Korean). For any other language the model words the one question in a step with no tools and no rules. The reply language comes from the writing system first, then the language the model named.
- A planned transit trip ends with one offer picked from the trip: the step-free way when an elevator on the route is out, a route with fewer transfers when an alternative has them, otherwise the return trip. It replaces the model's own "Want to start?".
- `prefer: "ferry"` is new on the planner. A trip that asks for a ferry says so when none goes there.
- No confirmations and no read-backs.

- Against the real model: `INFERHUB_BASE_URL=... INFERHUB_MODEL=lfm3 tsx scripts/eval-trip-questions.ts` runs nine messages in six languages and checks the stream, so no person reads the answers. It scored 7 to 8 of 9 across runs.

## What stays unchanged, and what does not work yet

- Walk and drive planning, the no-model fast path (it now hands a borough-wide trip to the model) and the place read-back are unchanged.
- The follow-up never suggests a time to leave: `docs/DESIGN_RULES.md` forbids it, so "leave later to skip a transfer" is offered as "want the route with fewer transfers?".
- A soft hint is still the model's call. LFM3 reads "with my grandma" as unclear, but marked "she walks slowly" as no hint and planned. The borough, start and hour checks are in code and always hold.
- The planners have no step-free option, so "step-free" tells the model to check elevators with `elevator_status` rather than filtering routes.
- Sometimes LFM3 writes no text after its tools; that was already so and is untouched.
