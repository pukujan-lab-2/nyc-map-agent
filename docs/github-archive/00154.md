# Issue #154: Adopt PCM 0.7.0, re-pin ACS 0.2.0 and ship the seat protocol so agents can claim seats

- State: closed (2026-10-21)
- Opened by Pukujan on 2026-10-21
- Original: https://github.com/Pukujan-lab/nyc-map-agent/issues/154

## Summary

Agents can't claim a seat or trust continuity state in this repo yet. `continuity preflight` reports `NOT_ADOPTED` because there is no `.continuity/config.json`. `stack-manifest.json` has four empty pins. Nothing on disk runs the seat protocol, so `.coord/boss_claim.json` has never been written. Alex approved one setup PR to fix this, in this repository only.

## What changes

1. Adopt Project Continuity Modules (PCM) 0.7.0 at `70dc17d` as an overlay. `context/BRIEF.md` stays the project contract, a new `checkpoints/CURRENT.md` is the current checkpoint, and `tasks/` holds task files. The issue-log-format 1.3.0 block goes into `AGENTS.md` and the PR template.
2. Re-run the agent-custom-setup (ACS) installer `acs_install.py` and fill the manifest pins from the certified release train: ACS 0.2.0 `470013e`, PCM `70dc17d`, the full eight-module Content Generation Modules (CGM) 0.5.12 at `100f3c3`, and Observational Issue Ops (OIO) 0.2.0 at `305adc5`.
3. Ship the pack's own `seat_protocol.py` as `.coord/bin/seat_protocol.py`, unchanged, so the first `join` writes `.coord/boss_claim.json`.

## Which ACS commit, and why

The release train (`agent-stack-train/stack-releases.json`) certifies ACS `470013e`. `589b0a9` is an older ancestor, and its `stack-mesh.json` asks for PCM and CGM commits that are older than the certified ones. The installer refuses those mismatches. Main is at `aea4f1b`, which changes only `stack-mesh.json` on top of `470013e`. The train skips mesh-only commits, so the component is still `470013e`. The installer ran from `aea4f1b` because that is the only tree whose mesh matches the certified PCM and CGM. The manifest pins `470013e`. The lock records the checkout actually used (`aea4f1b`).
