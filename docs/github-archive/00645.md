## What changes

- **Each turn is read from its own latest message.** `nearest_restroom` is hidden from the model unless the latest message asks for a restroom (in any of the app's languages) or is a short yes to the last answer. A message counts as a yes only when it is one or two words or starts with a yes in one of the eight app languages, so "get to times square" (four words) is a new destination. A new request also gets a line telling the model that earlier topics do not carry over. `server/features/agent/turn.ts`.
- **Nothing internal is spoken.** The reply passes through a filter a sentence at a time: a sentence that names a tool, a result field or a trip id is dropped, as is the model thinking aloud in its opening sentence ("Let me find the nearest restroom first…") and any reasoning printed before `</think>`. The rider still sees the answer build up sentence by sentence.
- **Raw data is cleaned.** The restroom tool returns today's hours as a phrase, and notes such as "Open later seasonally" are dropped.
- **Fewer model calls.** `transit_plan` now draws the route and opens the trip panel itself, where before the model made two more calls for `showRoute` and `openPanel`. After four tool calls the model must write its answer, so a turn cannot end with nothing said (one live turn made eight tool calls and said nothing).
- **Prompt.** Going somewhere is `transit_plan` straight away, never a route from memory; never ask whether they want walking or transit; never say tool names.
- **Traces.** Each tool span carries its arguments, a short result summary and an OK or ERROR status. The turn span says what kind of turn it was (`trip`, `asked`, `no-tool` or the first tool) and how many model calls it took.

## What stays unchanged, and what does not work yet

- Model choice, and the ask-or-plan slots from #626, are unchanged.
- I tried requiring a tool call on every new request. The Pro's llama-server ignores `tool_choice: required` and answers in text, so I dropped it; "get to X" reaching `transit_plan` rests on the hidden restroom tool, the new-request line and the prompt, not on a guarantee.
- Latency: a trip turn now makes two model calls, not three. The first call still took 2 to 13 s on the Pro (cold prompt cache), which this change does not touch.
- Reasoning printed before `</think>` is cut in the reply, but the llama-server's reasoning setting is the real fix and is outside this repository.
