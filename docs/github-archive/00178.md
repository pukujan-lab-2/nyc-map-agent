Choosing a neighborhood from "Jump to a neighborhood" in the Layers & filters drawer selected it but left the map where it was, so the jump looked broken.

## What changes
- The drawer now also moves the camera to the neighborhood, using the same centre-of-bounding-box target the search bar already used.
- That target and the drawer's jump logic live in one small helper, `src/lib/map/neighborhoodJump.ts`; the search bar uses it too.
- Each drawer option now carries its bounding box (one line in `Index.tsx`).

## How to verify
- New unit test `neighborhoodJump.test.ts`: it fails against the old behaviour (select without moving) and passes now.
- Locally: typecheck, all unit tests (151 passed, 8 skipped as before), lint, knip, dependency boundaries and the bundle size check (926.5 kB of a 927 kB budget) pass; project gates (PCM, CGM, ACS hotload) are valid.

## What stays the same
Tapping a neighborhood on the map still selects without moving the camera. No new dependencies. No conflict with the Layout A pull request #173 (checked with a trial merge).
