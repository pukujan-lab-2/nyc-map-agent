The product rule is show, do not tell, but agent answers had no buttons that draw them on the map.

## What changes
- The agent stream sends one `actions` line before `done` with a typed list of map actions. Older clients ignore lines they cannot parse.
- The server builds actions from tool results (`server/features/agent/mapActions.ts`); the model never writes them. Deduped, validated, ordered, capped at six.
- Actions: nearest restroom (draws it, turns the layer on, opens its card), route, skipped stops (from MTA alerts), a line's stops per ride leg, drive crash hotspots, fly-to for looked-up places.
- New `nearest_restroom` tool reading NYC Open Data's public restrooms (keyless, cached an hour, prefers open ones). Trips now carry a `skips` list, which the model also sees.
- Client: `AnswerActions.tsx` renders the buttons; `mapActions.ts` runs them through existing map-state, panel and trip-layer code; a points layer in `tripLayer.ts` draws stops and crash spots. On phones a tap closes the chat so the map shows.
