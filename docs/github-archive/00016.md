This adds an Octo data layer under the map, a small API over it, and a simpler dashboard. Stacked on #14 (ACS install).

## Schema (Octo workspace "nyc neighbourhood")
- **raw**: views over the existing `public.nyc_311_noise`, `public.nyc_crashes`, `public.nyc_311_rollup_hourly`. Nothing dropped or altered. New `raw.source_cells` holds registry sources rolled up per month and ~300 m block.
- **core**: `sources` (synced from the registry), `events` (noise + crashes with block, category, severity, street), `assets`, `block_areas` (block to NTA 2020, community district, borough), `areas`, `ingest_runs`.
- **marts** (materialized views + indexes): `block_month`, `nta_month`, `block_window` (90d/12mo totals + percentile), `street_stats` (green/yellow/orange/red levels for the walk bubble).
- Lineage diagram and how to add a dataset: `docs/DATA_MODEL.md`.

## Versioning and ingestion
- Two dbmate-format migrations in `db/migrations/`. `pnpm db:migrate` applies them through Octo's SQL endpoint and tracks `public.schema_migrations` like dbmate does. dbt goes on the list for when a direct connection exists.
- `pnpm ingest`: driven by the registry, incremental for noise and crashes (insert-only), month-by-month block rollups for the other sources, capped at 12 months. Then `pnpm db:refresh`.
- `.github/workflows/ingest.yml`: nightly at 03:30 New York time plus manual dispatch. It needs these repository secrets (I haven't set them): `OCTO_API_KEY`, `OCTO_WORKSPACE_ID`, and optionally `SOCRATA_KEY_ID`, `SOCRATA_KEY_SECRET`, `SOCRATA_APP_TOKEN`.

## API (Vercel functions in `api/`, also served by the Vite dev server)
- `GET /api/sources`: registry metadata, guides, filter options, last ingest
- `GET /api/blocks?source&window&level=block|nta|cd|borough&categories&severity&borough&nta`
- `GET /api/area/:row:col`
- `GET /api/street?name&borough`

All SQL uses bind parameters and zod-validated input. Responses carry `s-maxage=900, stale-while-revalidate`, and errors are `no-store`. Set `API_PROXY_TARGET` to proxy to `vercel dev` instead.

## Dashboard
- One **unit** dropdown (Block, Neighborhood NTA 2020, Community district, Borough) and one **style** dropdown (Filled areas, 3D columns, Heatmap). Filled areas are the default and use a ColorBrewer YlOrRd ramp. Community district shapes come from NYC Open Data `5crt-au7u`. Borough shapes are merged from the NTA polygons.
- Settings drawer: a top-areas list for the chosen unit, and a legend that matches the style.
- Sources drawer: a first-run "How to read this map" guide, a Filters section (borough, noise complaint types, crash severity, with options from `/api/sources`), and an "About this source" section per source (what, caveats, cadence). All of it sits in drawers, dropdowns and collapsibles, with no tooltips.
- `VITE_DATA_BACKEND=octo|socrata`. The default stays `socrata`, so nothing changes until it's switched on.
- Rules added to AI_RULES.md in #14: issue lifecycle, plus no tooltips and drawers/dropdowns only.

## Known limits
- Windows are month-aligned, so "90 days" can cover up to about 4 months.
- New noise rows from the ingest have no `nta2020`/`h3_r8`. The marts map them to areas through the block lookup instead.
- The classic Noise/Crashes layers still load through the browser worker (about 50 s headless). The registry source views use the API.
- One block (13630:-24621) holds 53k "Residential" noise reports. That looks like a geocoding default point in the city data.
