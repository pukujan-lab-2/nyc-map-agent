### Summary

Merges to main never reach the VPS, because nyc-map-agent has no GitHub to Komodo deploy. Every other service on the VPS has one: a Komodo stack, plus a check that redeploys when the GitHub branch moves. Until this one does, the VPS runs whatever was last built by hand, and nyc.design-bakery.com has no route to it.

### Identity and Lineage

Repository Pukujan-lab/nyc-map-agent, host `vps`. Follows #610 and #603, which made main describe the VPS. The pattern to copy is Octo's stack and its `octo-deploy-on-push` action in Pukujan-lab/server-management `komodo/resources/octo.toml`.

### Acceptance Criteria

1. `deploy/vps/autodeploy.sh` builds origin/main as an image tagged with its commit, swaps `nyc-map-web` to it, waits for its health check, and rolls back if that fails.
2. `nyc-map-web` joins the `study-os_edge` network so Cloudflare tunnel A can reach it by name.
3. A Komodo stack and a deploy-on-push action for nyc-map-agent exist in server-management, and `vps/PLAN.md` lists the app.
4. After a merge to main, the VPS runs that commit within about 5 minutes.

### Boundaries and Next Action

In scope: the deploy script and compose file here, and a pull request in server-management for the stack, action and plan entry. Out of scope: the Cloudflare public hostname for nyc.design-bakery.com, which is a dashboard change. Next action: open the pull request here.

### Symptoms

1. **Merges do not ship:** main has #598, #600 and #601, and the VPS still runs `nyc-map-agent:ecd8ba0`.
2. **No stack:** `komodo/resources/stacks-vps.toml` in server-management has no nyc-map-agent entry.
3. **No route:** tunnel A's routes, read from the `octo-cloudflared` logs, cover acs, octo, umami and other apps but not nyc.

### Hypotheses (unverified)

H1. A Komodo stack whose pre-deploy runs a repo script, triggered by a 5-minute action, deploys main the way Octo deploys production. **Status:** unverified. **Would confirm:** a merge to main appears on the VPS within 5 minutes. **Would refute:** the action runs and the running image does not change. **Experiment:** merge this change and watch `docker ps` on the VPS.

### Counter-signal

The app on the VPS is healthy today (`/healthz` answers 200 on 127.0.0.1:18088), so nothing is broken for anyone who reaches it; only the path from GitHub is missing.

### Honest Caveat

Komodo's stack and action have not been tried for this app. The Octo pattern is known to work, but this app's checkout belongs to `ubuntu` while Komodo's agent runs as root, so the script runs git as `ubuntu`.

### Problems vs Gaps

Problem: merged work does not reach riders. Gap: no Komodo stack, no deploy-on-push action, and no tunnel route for this app.
