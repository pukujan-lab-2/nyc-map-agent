# PR #642: fix(eval): stop scoring a dropped connection as an empty answer

- State: merged (2026-11-01)
- Opened by Pukujan on 2026-11-01
- Original: https://github.com/Pukujan-lab/nyc-map-agent/pull/642
- Branch `fix/629-no-default-shuttle` into `main`, +131 −9 in 6 files, merge commit 305e9c6e0aebf376f4757ab24afad45b27d29de9

A trial that could not reach the model was recorded as an empty answer, so the eval scored the network against the model and two runs could not be compared.

## Human outcome

When the line status eval says a change made things worse, that means the model read the reply worse. It no longer means the tunnel dropped.

## Before and after

**Before:** `scripts/eval-line-status.ts` caught a failed model call, set the reply to `""` and wrote a row anyway. The `empty-reply` check then counted it as a model failure. Two runs of the same 192 trials differed by 6 empty replies in one and 12 in the other, purely from a dropped SSH tunnel to the MacBook Pro.

**After:** each trial retries the call three times with a growing wait. If the model still cannot be reached, the run stops with a message naming the case and saying to check the endpoint, and writes no row for it. A run that could not reach the model is not a run.

## Change and scope

- `scripts/eval/line-status/retry.ts` (new): `withRetry` and `UnreachableModel`, with `retry.test.ts`.
- `scripts/eval-line-status.ts`: the trial call goes through `withRetry`, and a `type: "error"` event in the stream now counts as a failed call. That last part matters: the route reports an unreachable model as an error event on an otherwise fine response, so the first attempt at this fix did nothing until it was added.
- `docs/eval/line-status/PROGRAM.md`: rule 7, that a run which cannot reach the model is not a run.
- `docs/eval/line-status/LEDGER.md`: the rejected iteration from this session, written up so the next run does not repeat it.

## What stays unchanged

The checks, the cases and the comparer. This changes what counts as a trial, not how a reply is judged. The app itself is untouched.

## Verification

- `npx vitest run scripts/eval`: 15 tests pass, including the retry backoff and the "no row recorded" message.
- `npx tsc --noEmit` and `npx eslint` on the changed files are clean.
- With the tunnel deliberately down, the runner exits 1 naming the case instead of writing `empty-reply` rows. Before the fix it wrote a row with an empty reply and carried on.

## The measurement this session produced

The baseline and one iteration ran on LFM3 before the fix, so both carry the empty-reply noise. The comparer said reject, and that verdict holds after removing the failed calls:

| | baseline | shuttle change |
|---|---|---|
| train, all trials | 45.4% (64 of 141) | 73.0% (103 of 141) |
| held-out, all trials | 49.0% (25 of 51) | 23.5% (12 of 51) |
| held-out, excluding unanswered trials | 52.1% (25 of 48) | 30.8% (12 of 39) |

The change cut invented shuttles from 67 trials to 5, which confirms the prompt line was the cause. It also moved the failure rather than removing it: `denies-trouble` rose from 3 to 28. The prompt change was dropped, not merged.
