# Issue #368: Make the first load fast: shell first, last real data, lazy everything else

- State: closed (2026-10-25)
- Opened by Pukujan on 2026-10-24
- Original: https://github.com/Pukujan-lab/nyc-map-agent/issues/368

A cold load fetches a lot before the map is useful. The first screen should appear at once and fill in from cached real data.

## What is needed
1. Instant shell: the flat map and the chat bar render with no data request blocking them; 3D code loads only on tilt.
2. Last real data, never mock data: keep the previous visit's data in IndexedDB, show it at once labelled "updated N min ago", refresh in the background. (The neighbourhood rollup is already cached in `localStorage`.)
3. One bootstrap request for what the first screen needs: nearby live trains, active alerts, saved places.
4. Daily and 7-day data (noise, crashes, restrooms, segment history) become static files written by the nightly ingest and cached for a day.
5. Everything else loads when its layer opens or the agent needs it; likely next data prefetches at low priority when idle.
6. Load by viewport where it helps (restrooms near you first).

## Acceptance criteria
- [ ] The map and chat bar appear before any data request completes.
- [ ] A repeat visit shows real data immediately, with its age.
- [ ] Time to first map and request count measured against the baseline.
