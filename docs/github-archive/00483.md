# PR #483: fix(follow): stops list starts at the train's next stop

- State: merged (2026-10-26)

**Problem.** While you follow a train, the sheet's stops list could show the stop the train had just left (for example "Sterling St, 0 min") above the next stop that the sheet's top line names ("Next: President St, 1 min"). The list was cut by time and kept a stop up to 30 seconds after its time, while the top line uses the train's own next stop.

**What changes.** The list now starts at the train's next stop, or at the stop it is standing at. Stops are matched by station, so platform ids still match. Time decides only when the next stop is unknown.

**How to verify.** Run `pnpm exec vitest run src/features/transit/followInfo.test.ts`. Three new tests cover: starting at the next stop, matching by station, and falling back to times.

**Stays unchanged.** Bus stops (they come from the bus trip's own list), the sheet's layout, and the strip.
