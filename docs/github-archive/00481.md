## Problem

The `contract` job (Schemathesis checking the live site against `openapi.json`) has failed on every main push since 22:58 UTC today, so main shows red even though deploys succeed. The crash is inside Schemathesis's own dependency, not our API: `AttributeError: 'many' object has no attribute 'more'` (9 passed, 19 runtime errors; example run 40244937957).

Cause: Hypothesis 6.170.10 was published at 22:43 UTC, between the last green run (22:33) and the first red one. `uvx schemathesis@4.0.0` resolves the newest Hypothesis allowed (`<7`), and 6.170.10 removed an internal that Schemathesis 4.0.0 uses.

## What changes

`.github/workflows/ci.yml`: the contract step runs `uvx --with 'hypothesis<6.170.10' schemathesis@4.0.0 ...`. Everything else in the command is unchanged.

I also tried upgrading to Schemathesis 4.32.5 instead. That reports a schema error on `GET /api/v1/events` because it reads our valid OpenAPI 3.1 `prefixItems` (the `[lon, lat]` tuple) as an invalid `items` list. That's a Schemathesis problem, not an API bug, so I kept 4.0.0 and pinned Hypothesis.

## How to verify

Locally, from this branch, the same command as CI:

```
uvx --with 'hypothesis<6.170.10' schemathesis@4.0.0 run openapi.json --url https://nyc.design-bakery.com --exclude-method POST --exclude-path-regex '^/api/(?!v1/)|/vehicle-models/' --max-examples 2 --phases examples,fuzzing --checks not_a_server_error,response_schema_conformance,content_type_conformance --rate-limit 3/s --request-timeout 20
```

Result: all 28 selected operations tested, 50 of 50 generated cases passed, no issues found. The same command without the pin reproduces the 19 runtime errors.

`contract` only runs on pushes to main (`needs: deploy`), so this PR's checks can't show it. The first main run after merge is the real proof.

## What stays the same

No real API findings turned up. Schemathesis printed two existing warnings that don't fail the job: one route returns 404 for generated input (`/api/v1/storefronts/logo`), and a few routes reject most generated parameters. Deploy and every other job are untouched.

Next action: remove the pin once a Schemathesis release supports Hypothesis 6.170.10+ and reads 3.1 `prefixItems` correctly.
