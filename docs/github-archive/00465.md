## Problem

When someone shared their location, the assistant sent their exact position as numbers to the AI model service (InferHub, which forwards requests to outside model providers). The numbers went into the model's instructions, and the `geocode` tool returned the exact point for "here". The privacy page (`docs/PRIVACY.md`) flagged this as its first gap, and stayed a draft until it was settled.

The owner chose to fix it first, then approve the page.

## What changes

- **Instructions:** they now say "The user shared their location" (or "in street view") with no numbers. The model uses "here" in its tools, and the server fills in the exact point.
- **Tool results:** before a result goes back to the model, any point within about 150 metres of the user becomes `"here"` (`hideHere` in `server/features/agent/tools.ts`). Other places, such as restrooms and exits, keep their positions. The map still gets exact points, because map commands go straight to the phone.
- **Street view:** in street view, "here" now means the spot on screen, as the instructions already said. Before, a shared location overrode it.
- **Privacy page:** `docs/PRIVACY.md` is marked approved and matches the code. The in-app **Data policy** now states the rule in all eight app languages instead of "a draft, not a published policy yet".

## How to verify

- A route test sends a question with a shared location and checks that the model's prompt contains no part of those numbers, and that nothing is logged.
- A tools test checks that `geocode` of "here" gives the model `"here"`, while `flyTo` still moves the map to the exact point.
- All unit tests pass, along with the type check and lint.

## What stays the same

What the phone stores, **Delete everything**, the fair-use limit and the timing log are unchanged. Gaps 3 and 5–7 on the privacy page are still open, and the page lists them.
