**Problem:** a which-exit answer stayed a small card only because the model was told not to open the trip sheet; nothing stopped it if it did. Checking that on the live site showed a worse bug: answering "yes" to "Want to start?" failed every time. The trip the answer planned only lived for that one request, so the next request's showRoute got an unknown trip id and the reply said the route couldn't load.

**What changes:**
- In the same request as `station_exit`, `showRoute` and `openPanel` send nothing and tell the model to ask "Want to start?" first.
- Planned trips are kept in memory for 30 minutes (up to 2000, oldest dropped first), shared across requests, so the yes draws and opens the same walk. This also fixes yes after restroom and walk answers, which use the same store. The site runs one server instance; a redeploy clears the store, and the model then plans again (the error now says so).

**Verify:** `pnpm exec vitest run server/features/agent/tools.test.ts`: the new test runs `station_exit`, checks both trip tools are held off in that request, then opens the same trip from a new request. Live check after deploy: ask "Which exit at Times Sq-42 St for Bryant Park?", then "yes".

**Unchanged:** the prompt, the client, and what other answers draw.
