### Summary

The app people use runs on the VPS, built by hand from `feat/motis-planner` (a branch with no pull request), while main on GitHub still says it runs on gravebuster. gravebuster went offline on 2026-10-31, so every merge to main since then ends in a failed `deploy` job, and none of those merges reach the VPS. GitHub is supposed to be the authority for what is live, and right now it is not.

### Identity and Lineage

Repository Pukujan-lab/nyc-map-agent. The live build is image `nyc-map-agent:ecd8ba0` on the VPS (`ssh vps`), from branch `feat/motis-planner`. Fix in flight: #603.

### Acceptance Criteria

1. The code the VPS runs is on main.
2. `deploy/README.md` and `deploy/PROJECT.json` name the VPS as the host and say how it is deployed.
3. The `ci` workflow on main no longer fails by calling the offline gravebuster deploy API.
4. `checkpoints/CURRENT.md` says where the app runs.

### Boundaries and Next Action

In scope: this repository's code, deploy docs, CI workflow and checkpoint. Out of scope: adding nyc-map-agent to server-management's `vps/PLAN.md` and Komodo stacks, and the Cloudflare route for nyc.design-bakery.com; both need the owner's direction in other places. Next action: merge #603.

### Symptoms

1. **Red deploy on main:** the `deploy` job of `ci` failed with HTTP 530 on 983731a, 853778a and 2af0c90.
2. **Public site down:** https://nyc.design-bakery.com answers 530.
3. **Live code not on main:** the VPS runs `ecd8ba0` from `feat/motis-planner`, which had five commits not on main and no pull request.
4. **Docs name the wrong host:** `deploy/README.md` and `deploy/PROJECT.json` describe gravebuster.

### Hypotheses (unverified)

H1. The 530 on the deploy job comes from gravebuster being offline. **Status:** confirmed. **Would confirm:** Tailscale shows gravebuster offline. **Would refute:** gravebuster reachable while the job fails. **Experiment:** `tailscale status` showed it offline, last seen about 21 hours earlier; SSH timed out.

H2. The public 530 comes from no tunnel routing nyc.design-bakery.com to the VPS app. **Status:** unverified. **Would confirm:** the Cloudflare tunnel config has no route for that name. **Would refute:** a route exists and points at 127.0.0.1:18088. **Experiment:** the routes in the VPS tunnels' logs list other design-bakery.com names but not nyc; the dashboard was not checked.

### Counter-signal

The VPS app itself is healthy: `curl http://127.0.0.1:18088/healthz` on the VPS answers 200, so the outage is in routing and records, not the app.

### Honest Caveat

The tunnel routes were read from container logs, not from the Cloudflare dashboard, so H2 is not proven.

### Problems vs Gaps

Problems: the failing deploy job, the public 530, and main missing the live code. Gaps: nyc-map-agent has no Komodo stack and no entry in `vps/PLAN.md`, so there is no sanctioned GitHub to VPS deploy path yet.
