## Problem

At street level the app had no street names to work with. Corner street signs and the "which corner is this exit on" lookup read the basemap's street-name data, and in street view that data was empty: 0 street names within 150 m at Union Square. Entrance labels ("6 Av & W 47 St · SE corner") need it too.

The cause is the same as #502. Walking hides the basemap's text labels, and those were the only style layers that use the street-name source layer (`transportation_name`). Past the tiles' max zoom, MapLibre keeps only source layers that some style layer uses, so the names were dropped from the tiles at street level.

## What changes

- One invisible circle layer on `openmaptiles` / `transportation_name` (zero radius, zero opacity), added next to the #502 keep layers in `installCity3d`. Nothing new draws.
- Places (`poi`) didn't need it: walking already shows the shop icon layer, so they stay in the data (24 within 150 m both with and without this change).

## How to verify

In the dev build, open street view at Union Square. Then in the console, `querySourceFeatures("openmaptiles", { sourceLayer: "transportation_name" })` near the camera:

- before: no names;
- after: 7 (Broadway, Union Square West/East, E 16 St, E 17 St, …).

Checked with a fresh page each time. Type check and lint pass locally; unit tests and e2e run in CI (local runs skipped, the Mac is short on memory).

## What stays the same

The overhead map, label visibility while walking, and the shop and restroom fixes from #502 and #503.
