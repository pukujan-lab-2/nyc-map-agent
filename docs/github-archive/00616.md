### Summary

`continuity validate` fails on main because the generated document index (`docs/CONTINUITY_INDEX.md`) still lists `AGENTS.md` as reviewed at an older hash. The stack upgrades in #600 and later changed `AGENTS.md` without refreshing its review record.

### Identity and Lineage

Repository Pukujan-lab/nyc-map-agent. Files: `.continuity/documents.json` (review records) and `docs/CONTINUITY_INDEX.md` (generated). Listed as item 3 under Next in `checkpoints/CURRENT.md`.

### Acceptance Criteria

1. `continuity validate` reports no errors.
2. The `agents` record in `.continuity/documents.json` names the current `AGENTS.md` hash, after someone has checked that its summary still describes the file.
3. The Next item about refreshing the index is gone from `checkpoints/CURRENT.md`.

### Boundaries and Next Action

In scope: the review record, the regenerated index, the checkpoint line. Out of scope: the `HANDOFF.md` warning (a local untracked file). Next action: refresh the `agents` record and render the index.

### Symptoms

1. **Validate fails:** `continuity validate` prints "generated document index is out of date" and exits invalid.
2. **Hash mismatch:** the index says `AGENTS.md` is CURRENT at `17f5f43f…`, while the file now hashes to `679d2bcc…`.

### Hypotheses (unverified)

H1. Refreshing the `agents` record and re-rendering clears the error. **Status:** unverified. **Would confirm:** `continuity validate` passes afterwards. **Would refute:** another document shows up stale. **Experiment:** run `continuity docs refresh agents`, then `continuity docs render`, then validate.

### Counter-signal

Nothing reads the index at runtime, so the app is unaffected.

### Honest Caveat

Marking a document reviewed is only honest if someone read it: the summary was checked against the current `AGENTS.md` on 2026-11-01.

### Problems vs Gaps

Problem: the continuity check fails on main. Gap: stack upgrades do not refresh the review record of the files they change.
