Asked "I need to go to the 3 Percent Club event today, where is it", the agent had nothing to search: the city's event feeds only cover permits and Parks programs. So it could only say it didn't know. This adds an on-request event lookup.

## What changes

- **Two new agent tools** (`server/features/agent/webLookup.ts`):
  - `find_event` searches the web for a named event in New York through the TinyFish search API.
  - `read_page` reads one event page (Luma, Eventbrite, the organiser's site) through the TinyFish fetch API.
- **How the agent answers:** it gives the venue, address and time as the page states them, calls `geocode` so the venue appears on the map, and offers to plan the trip. If the page gives no venue or time, it says so and never guesses (rule in `server/features/agent/prompt.ts`).
- **Sources:** both tools record a source ("Web search (TinyFish)" and "Event page"), so the answer's "i" shows where the facts came from.
- **Safety:** `read_page` only reads public http(s) pages, never local or private addresses.
- **On request only:** it only runs when someone asks about a specific event, in line with the no-unasked-suggestions rule. Nothing is crawled or stored.

## How to verify

- **Local checks:** type check, lint, dependency rules, knip and OpenAPI all pass. 967 unit tests pass, including `webLookup.test.ts`, which uses fake responses and covers the no-key case and the private-address block.
- **Live calls:** both calls returned real results with the owner's TinyFish key, run locally.
- **On the server:** set `TINYFISH_API_KEY` in the production environment, then ask about a named event. Until it's set, the agent says event lookup isn't set up.

## What stays the same

No UI or data changes, and no migration.
