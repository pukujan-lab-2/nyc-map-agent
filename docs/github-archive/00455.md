# PR #455: perf(home): chat bar paints before the app's script runs

On a phone, the page stayed blank for about 5 seconds: nothing was drawn until the 612 KB main script had downloaded and run. Now the map-coloured page and the chat bar appear after about a second, and you can start typing while the rest loads.

Closes #368

## What changes

- **`index.html`** carries a static first screen: the map's ground colour and a chat bar that looks like the real one, with "Ask anything…" and the blue button, styled inline so it needs no script or stylesheet.
- **`AgentHome.tsx`.** When the real chat bar appears, it takes any text typed into the static one and removes it, so the bar never blinks out and nothing typed early is lost.
- **`src/lib/shellDraft.ts` (new)** reads and removes the static bar. **`main.tsx`** removes it after 30 s as a fallback, in case the assistant is switched off or fails to load.

## How it was checked

- **First paint drops from 4.9 s to 1.1 s.** Lighthouse 13.5.0's mobile preset (CPU 4× slower, slow 4G), median of three runs. Both builds were served locally in the same way, one from main and one with this change.

  | Build | Score (out of 100) | First paint | Ready to use | Main bundle script time |
  |---|---|---|---|---|
  | main | 39 | 4.9 s | 9.4 s | 3.1 s |
  | this change | 50 | 1.1 s | 8.5 s | 3.1 s |

  Ready-to-use time and script time are within run-to-run noise. This change makes the page appear sooner, not run faster.
- **The bar shows before any data arrives.** In a phone-sized browser with the CPU slowed 4× and the app's script held back 4 s, the static bar showed after 0.15 s. The first API answer on the live site arrives at about 5.3 s under the same slowdown.
- **Typing carries over.** Text put in the static bar ("nearest restroom") was in the real bar when it appeared at 6.4 s, and the static bar was gone.
- Typecheck, lint, the module-boundary check and every unit test pass (1235). New tests cover the hand-over and the removal.

## What stays the same

The real map still draws only once the main script has run, about 5.5 s on that phone. Making that sooner means splitting the main bundle, which is a larger change. The other first-load parts of #368 are already on main: the last visit's line shapes and stations come back from IndexedDB, the browser's built-in database (#442), and the crime and noise summaries load only when an analytics layer is on (#434).
