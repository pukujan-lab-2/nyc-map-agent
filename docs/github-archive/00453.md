`src/lib/map/threeLayer.ts` held seven separate 3D layers in one 1,900-line file, so any change to one layer meant reading all of them. This splits it into one module per layer with no change in behaviour.

Closes #219

Builds on #452 (three.js 0.186.1), which has merged.

## What changes

| Module in `src/lib/map/three/` | Holds |
|---|---|
| `core.ts` | `sharedRenderer` (one WebGL renderer per map context), colour and light settings, `movedM`, `MercatorCoordinate` |
| `vehicles.ts` | live trains and buses, elevated structure, station entrances, x-ray |
| `hydrants.ts` | fire hydrants |
| `streetSigns.ts` | corner street-name signs and road-surface names |
| `furniture.ts` | bus stop flags and LinkNYC kiosks |
| `storefronts.ts` | storefront signboards and facades |
| `landmarks.ts` | hero landmark models and their GLB export |

- `threeLayer.ts` is now a 14-line entry that re-exports the same public names, so no caller changes.
- The dependency-cruiser rule that keeps three.js in one place now allows `src/lib/map/three/` as well as the entry and `streetSigns.ts`. `docs/MODULES.md` and `AI_RULES.md` name the folder.
- `core.test.ts` covers the rebuild distance and the light scale.

## How it was checked

- Typecheck, lint, the boundary check and every unit test pass (1234 tests).
- Size limits pass. The shared 3D chunk is 148.8 kB against 148.6 kB before the split, and all JavaScript is 1052.6 kB, so the split costs nothing measurable.

## What stays the same

Every exported name, every layer id and the lazy `threeLayer` chunk. The code inside each layer moved without edits, apart from import lines and one local alias (`eyeLngLat`) repeated where two layers use it.
