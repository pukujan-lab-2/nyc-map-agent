# PR #550: fix: shop sign logos answer fast when OpenStreetMap's Overpass is slow

**Problem.** In street view, each shop sign asks `/api/v1/storefronts/logo?name=…&lon=…&lat=…`. Matching the name to a brand asks public Overpass servers; while they are slow, the server tried three hosts at 25 s each and remembered nothing, so every sign on the street waited again and Cloudflare cut it off with a 502 after ~50 s (seen live on a phone, 2026-10-27). Signs still showed names, but the connections piled up.

**What changes** (`server/features/storefronts/routes.ts`)
- Each Overpass host gets 8 s instead of 25 s.
- A cell whose lookup failed answers `404 no_brand` straight away for 10 minutes (the sign shows its name, as with no logo), then tries again.

**How to verify.** New test in `routes.test.ts`: an Overpass outage answers 404 and the second sign in that cell makes no new upstream call. Live: `curl` a name lookup returns in seconds, not a 502.

**Unchanged.** Lookups by `qid`, the logo copies and their licence check.
